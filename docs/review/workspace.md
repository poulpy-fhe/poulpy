# Workspace review rules

This file holds the rules that apply to more than one crate; the crate files under `docs/review/` add only their own rules.

## 1. Workspace

- **Dependency direction.** hal depends on no poulpy crate, core on hal, ckks, bin-fhe and mhe (scheme modules included) on hal and core, blas on hal, core and ckks; library crates never depend on `poulpy-cpu-*`, even as dev-dependencies, backends take scheme crates only behind `enable-<scheme>`, poulpy-cpu-rayon depends on poulpy-cpu-portable, never the reverse, and poulpy-cpu-oracle and poulpy-bench are dev-dependencies only.
- **No backend in library crates.** Library crates (hal, core, ckks, bin-fhe, mhe, blas), rustdoc, comments, contract docs, suites and doc examples included, name no concrete backend type, backend crate or ISA ("an FFT backend" is generic); registrations, attestation routes, runnable examples and build commands belong in backend crates, READMEs and `docs/`, and per-target math routing is not a backend.
- **Runnable examples.** Core and scheme examples live in `backends/poulpy-cpu-portable/examples`, each `[[example]]` entry's `required-features` enabling its layer; ISA crates keep only HAL-level examples of their own backends and bench binaries, and host-math examples may stay in their crate.
- **One shared version.** All workspace crates carry the current `version`, bumped only by the release commit; `[workspace.dependencies]` gives published crates `path` plus `version`, unpublished ones (`publish = false`) `path` only and only as dev-dependencies of published crates.
- **Package metadata.** Published crates set `edition = "2024"`, `license = "Apache-2.0"`, an existing `readme = "README.md"`, a `description`, `repository` and `homepage` (the GitHub repository) and `documentation = "https://docs.rs/<crate>"`; unpublished ones `publish = false`; feature-dependent backends `[package.metadata.docs.rs] all-features = true`.
- **Workspace dependencies.** Dependencies are declared once in the root `[workspace.dependencies]` and used as `{ workspace = true }`, inline versions only for target-specific or optional platform ones, and resolution changes commit `Cargo.lock` in the same diff.
- **Setup math dependencies.** `astro-float-num`, `libm`, `dashu-float` and `dashu-int` keep compatible ranges, never `=` pins, and moving one passes the CKKS determinism fixtures unchanged or states the setup-bit change in the CHANGELOG.

## 2. Design rulings

- **The reference is the implementation.** The `reference` and `oep::derived` bodies (HAL basis operations: their contract blocks) define the result (values, rounding, metadata and canonical flag, input mutation, refusals and their point, draw order), which an override reproduces bit for bit, choosing only kernels, prepared form and scratch size within its own query.
- **Overrides need parity.** Every override has a registered bit-exact parity test against the oracle or a backend attested for those operations and ranges, never itself or an unattested sibling.
- **Backend agnostic.** Generic code (`api`, `delegates`, `oep`, `reference`, derived bodies) uses only backend views (`*ToBackendRef<BE>`, `*ToBackendMut<BE>`, `*BackendRef<'_, BE>`, `*BackendMut<'_, BE>`), no host bound (`HostDataRef`, `HostDataMut`, `HostBackend`, `HostVisibleBackend`, `HostStaged`), host view (`to_ref`, `to_mut`), accessor (`at`, `at_mut`, `raw`), host helper (`to_host_owned`, codecs, `stats`, `digest_u64`) or round trip, except in serialization, host-named codecs, host-built LUTs and plans, diagnostics, decrypt-to-value helpers, bench staging and tests.
- **Word-generic code.** Layouts, containers and generic code stay generic over the coefficient word (`W: ZnxWord`, `BE::ZnxWord`), and code working only for `i64` words says so with a `ZnxWord = i64` bound on the item needing it.
- **Sampling happens in place.** The backend draws every sampled quantity (errors, `u`, secret keys, floods, MHE masks) in place from a seed through `SamplingImpl` or HAL uniform fills, never via a host default body, host staging or scheme-code `Source` draws; a new quantity is a new `SamplingImpl` method.
- **Caller owns modules and scratch.** Library code calls no `Module::new` and takes no `ModuleNew` bound, host modules included, outside tests, examples, benches and tuning tools, and operations never allocate a scratch arena (`ScratchOwned`): the caller supplies per-worker arenas, each with its own module, and only a no-arena setup API its crate file names allocates one.
- **Every operation through the OEP.** Every method of a `Module<BE>` API trait that reads or writes an operand, its `_tmp_bytes` and `_galois_elements` queries included, dispatches through a same-named OEP method whether or not a backend specializes it, required or an `oep::derived` default, the rule leaving out only allocation and sizing (preparations and decompressions dispatch like any operation), information computed from module parameters alone (slot counts, the Galois element of a rotation), aggregate queries taking the maximum of selected queries, host-named adapters, host-only diagnostics and stateful helper objects; a fused variant (API method, override or kernel) needs a bench showing the composition too slow and stays bit-exact with it, and replacing a required method or fused override by the composition needs a bench showing it no slower.
- **Exactness without switches.** HAL integer results are exact under their operand bounds, floating-point transform backends rounding back to them, with no exact/approximate switch (`DFT_IS_EXACT`-style constant, precision gate) or path depending on one; `NegacyclicFFT` is the one documented floating-point operation.
- **Vector-matrix products.** A vector-matrix product over prepared data (public-key encryption, `sum_l u_l pk_l`) is one VMP, never per-entry products and additions.
- **Policy stays with the caller.** The library keeps no per-width key store or key-selection policy, exposing information queries (Galois elements, key widths, layouts and uses) and looking keys up through caller sources at the width it needs.
- **Every algorithm path stays exposed.** Every algorithm path (product strategies, BSGS schedules, prepared or streamed operands) stays caller-selectable and bit-exact against its own reference circuit, never picked implicitly (optimal-choice helpers are opt-in); a runtime predicate chooses between paths only when they give identical bits, routes to a fallback only the inputs the main path cannot run (core's per-giant linear-transformation fallback), or selects a label-proven specialization, core's one-pass relinearization gate being the one exception.
- **Label-proven specializations.** A predicate may send inputs to a cheaper circuit giving other bits only when it reads operand metadata alone (labels, batch records, shapes; never data, a measurement or the backend), that metadata proves the circuit computes the general path's message, and the circuit spends no more scale, key switches or plaintext products than the general path, with keys inside the operation's key set; the specialization keeps its own reference circuit, its own `# Metadata` column and tests on both sides of the predicate.
- **Exact gadget decomposition.** Every GGLWE gadget product (key switch, automorphism, relinearization, trace, packing, linear transformation, LWE conversion, blind rotation, GGLWE and GGSW key operations, scheme paths over them) refuses an input wider than the key's `max_input_k` before any write and decomposes exactly, except the gated one-pass relinearization tail past the gadget when `cnv_offset mod base2k > 0`, its input width still checked.
- **Plaintexts allocated once, dense.** A plaintext is allocated once at its width, never relabelled (`k`, scale), and dense at its own degree `n` dividing `N`.
- **No multiparty CGGI.** No multiparty (threshold or collective) blind-rotation, circuit-bootstrapping or BDD key, or protocol producing one, uses the CGGI marker (multiparty blind rotation waits for its own automorphism-based, LMKCDEY-style, marker in poulpy-bin-fhe); collective GGSWs are allowed.
- **Minimal code.** Changes add the least code meeting the contract: no duplicate of any workspace item, backends included, under any name (the finding names it and its path); a generalized feature (parameter, bound, slice argument, wider layout) over a near-duplicate sibling while contract, reference circuit and bit-exactness hold, or the PR says why not; the shortest composition at equal result and cost; no copied logic; parallel operand lists, never pairs, for sums and dot products, the lower layer changing rather than callers collecting: slices (`a: &[&A], b: &[&B]`), or `ExactSizeIterator + Clone` inputs where an in-tree caller, named by the PR, derives the operands from another structure (a field of each element, a transform's diagonals) and would otherwise collect references; their lengths and every term checked before any write.
- **Minimal visibility.** A free function is private, `pub(crate)` only if another module of its crate calls it, and `pub` only for a caller in another crate that no public API serves, named by the PR (exceptions: section 14).

## 3. Layering and dispatch

- **One layering model.** API traits, delegates, OEP families, reference and derived bodies, opt-in selection and overrides follow one model in every crate, poulpy-hal's for basis operations and poulpy-core's above it, documented once in `docs/guides/layering-contract.md`, which crate contracts docs link instead of restating.
- **What a new operation needs.** An API method (and trait when new), a delegate, a reference or derived body (hal: a contract block, a portable kernel and, when required, an oracle body) and its opt-in macro arm (new family: every umbrella macro and registration list; none for a `SamplingImpl` method or a CKKS coefficient-encoding hook).
- **One family per layout.** An operation on a layout lives in that layout's API module and OEP family (`api::mat_znx`, `HalMatZnxImpl` for `MatZnx`), even at the cost of empty `unsafe impl`s, and every caller in any crate uses it.
- **One file name per family.** A family has same-named files under `api/`, `delegates/`, `oep/`, `reference/` (and `oep/derived/`), hal using `oep/hal_impl.rs` and `oep/derived.rs`; crate files state per-operation splits.
- **Delegates are a plain dispatch.** A delegate (the blanket `impl Api<BE> for Module<BE>`, bounded only by the OEP trait and documented fences such as hal's `Backend<ZnxWord = i64>`) is only `BE::<method>(self, <every argument in order>)`, forwarding every call unchanged and checking nothing; layout conversions belong in `oep::derived`, operations without an OEP method (aggregate queries, host adapters, `TransferInto`) in their `api` module, and the private `delegates` module holds only these impls and local macros.
- **Selection is explicit.** Per backend and OEP family exactly one of the opt-in macro or a hand-written `*Impl` exists, the latter forwarding the other required methods and their queries to the public `*_reference` functions and keeping the derived defaults (hal: to the portable kernels or OEP defaults), the former being, above hal, a `#[macro_export]` macro on `($be:ty)` (crate files name further parameters) that implements `$crate::oep::<Family>Impl` for `$be` with every required method, and only those, forwarded unchanged to its `<method>_reference` and keeps the derived defaults; no blanket implementation selects a reference by bounds or on import.
- **Overriding one family.** A backend overriding one family replaces each umbrella holding it (`impl_<crate>_reference_full!`, a group umbrella, `impl_cpu_<scheme>_defaults!`) with that umbrella's other registrations and hand-writes only the overridden `*Impl`.
- **Compositions use selected implementations.** Derived defaults, nesting references and aggregate queries reach constituents through `BE::` or the public API, sized by selected queries (`module.<op>_tmp_bytes(..)`) at the passed layouts, never via another operation's `*_reference` body or query, a worst-case layout, a kernel or themselves, except shared helpers without API or OEP form (`gglwe_product_dft_reference`).
- **No reference outside the macros.** `api`, `delegates`, `oep` (derived bodies included) and `layouts` name `crate::reference` only in opt-in macro bodies and rustdoc links, and a helper shared with code outside a `reference` module (these modules, another crate's non-reference code, a backend override: checks, sizing, placement, pure math, host plan-material generators and encoders) lives outside `reference`, which imports it, refusal checks in `layouts/validation.rs` (`layouts/validate.rs` in blas) and other helpers in a non-`reference` module.
- **Required versus derived.** A method only composing operations of its own layer (core OEP methods in core, mhe ones in mhe) is an `oep::derived` default whose default body, query defaults aside, is one call to its `<op>_derived`; required methods are basis operations, bodies calling a lower layer (a key switch over HAL products, a preparation over `vmp_prepare`), or methods whose signature cannot carry the composition's scratch, as their OEP doc states.
- **Supertraits are the composition graph.** An OEP trait's supertraits are exactly the OEP families of its layer its default bodies dispatch through (`BE::` or the API they back), else `Backend`; a family only a reference body composes is a `where` bound of that `*_reference` method, a family generic over a method's own parameter (`CKKSEncodingImpl<F>`) a `where` bound of that method, and no other OEP method or delegate impl carries a `Module<Self>: <API>` bound (allocation and sizing traits, which have no OEP family, excepted).
- **One backend parameter.** An OEP trait is `pub unsafe trait XImpl[<scheme parameters>]: Backend`, its functions taking `module: &Module<Self>` first (the module constructor `HalModuleImpl::new` aside), never a backend type parameter or `where BE: XImpl<BE>` (non-backend parameters, an algorithm marker or integer type, allowed); a derived helper takes one backend parameter, the implementor.
- **OEP signatures mirror the API.** An OEP method takes `module: &Module<Self>` then the API method's exact parameters, generics and types, in order and by name, except internal hooks without an API twin, called through `BE::` (`glwe_mul_columns`), taking what their caller hands them, as their doc states.
- **OEP contract docs.** Each OEP method's doc names the body it reproduces bit for bit, its `_tmp_bytes` bound and its freedoms, and the trait's `# Safety` states only the obligations its methods share, never only "must satisfy the contracts of all trait methods", pointing to `poulpy-hal/docs/backend_safety_contract.md` for memory, layout, synchrony and aliasing (hal: its contract blocks).

### 3.1. Constructing a reference implementation

- **Compose the layers below.** A reference composes lower-layer operations (core over HAL, scheme crates over core and HAL, blas over CKKS), looping only over public dimensions (columns, rows, digits, terms, steps) and leaving coefficient arithmetic to kernels.
- **Gadget rows through core.** Every gadget row's plaintext `pt * 2^-(k_offset + (row + 1) * k_digit)`, in core, bin-fhe and mhe alike, is written with core's `gadget_row_plaintext`, never added to a limb by hand.
- **Write the production algorithm.** A reference, the production circuit, reuses existing vector, matrix, convolution and prepared-operand operations and minimizes normalizations, transforms, copies, full-buffer passes and live temporaries.
- **In-place forms read first.** An `_assign` form reads all it needs from `res` (its normalized or prepared copy, metadata) before its first write to `res`, writing each column after its last read, or uses a scratch copy.
- **Keep specialization in the backend.** ISA kernels, prepared-layout assumptions and hardware tuning live behind OEP overrides or capability contracts, with parity and a bench, never in a reference.
- **Validate independently.** A new or changed reference is tested against its mathematical or noise model and edge cases, not only parity, and a change to its rounding, mutation, refusals or draw order is a `**Breaking, behaviour:**` CHANGELOG entry stating fixture updates.

## 4. Validation and errors

- **Checks live once.** Each check lives once where the result is defined: the hal kernel entry (an `oep::derived` body for multi-call preconditions), the reference or derived body above hal (shared validators allowed), an undispatched operation's API method (`TransferInto`, host adapters), allocation or construction for layout invariants; never a delegate or a second layer, though compositions pre-check inner calls.
- **Check before the first effect.** Every precondition (key coverage, scheme budget and scratch included) is checked before the first output data or metadata write (canonical flag, noise, scheme stamps, batch records, a metadata-clearing borrow) or draw, list checks in their own pass, keys resolved before the first write and used as resolved, so a refusal leaves outputs, `&mut` inputs and sources unchanged (core borrows' noise clearing excepted).
- **Operand checks before scratch.** Operand checks (degrees, shapes, ranks, key coverage, typed metadata errors) precede the scratch-budget assert, which sits right before the first write.
- **Compositions pre-check inner calls.** A composition of dispatched calls checks before its first call every precondition a later call would reject, by the same criterion (`max_input_k`, Galois parity, layout equality), or, when every call applies the same criterion to the same layout, orders the work so a call that can reject runs before any write.
- **Release checks for caller input.** Caller-input checks are `assert!` or typed errors in every build (`const { assert!(..) }` on const generics), `debug_assert!` and `#[cfg(debug_assertions)]` serving only implied invariants and debug-only numeric scans.
- **Hot paths carry no checks.** Kernels validate once at entry: no `assert!` per limb or coefficient, no checked accessor (`at`, `at_mut`, `at_ptr`, `at_mut_ptr`, `raw`) or offset per coefficient, each limb slice taken once or raw pointers from one base; per-coefficient helpers use `debug_assert!`, unchecked ones are `unsafe fn ..._unchecked` with a `// SAFETY:` line citing the entry check, and a slice kernel's length check is its entry check.
- **Numeric bounds are caller obligations.** Numeric input bounds (digit ranges, headroom, transform exactness, representability) are documented, never scanned in release, readers included; debug scans sit under `#[cfg(debug_assertions)]` with a `# Panics` saying so.
- **Static messages on secret paths.** On secret-carrying paths (secret sampling and fills, secret preparation, DFT and products, key and share generation, encryption, decryption, secret conversions and transfers), messages format no value read from a secret-carrying operand (its data or its layout metadata) nor a scratch size from a secret-derived layout (public-operand and arena values may appear), compare such values with `assert!(a == b, "<literal>")`, never `assert_eq!`/`assert_ne!`, and show degrees only through a typed error's degree fields.
- **Message style.** Each new release check has a message naming the violated requirement ("operand degrees differ"), reusing pinned or shared messages verbatim ("operand column out of range", "operand degree exceeds the module degree", "<what>: windowed views are not supported here") and updating every pinning test in the same commit when one changes.
- **Overrides refuse like the reference.** An override, fused kernel or gated fast path, also inside a reference body (one-pass products, fused or lazy sums), rejects exactly what its reference or composed path rejects, before any write, with the same panic or typed variant in order: a failed precondition falls back or applies the shared check helpers (`assert_key_covers`, `check_degree`, `check_galois`), and metadata is stamped through the composed path's helper.
- **Scratch shortfall fails at entry.** An arena below the body's own query (`*_tmp_bytes_reference` for a direct reference call; a CPU parallel kernel: one worker's share) fails at entry, not at the carve backstop "insufficient scratch arena capacity": a panic in hal, core, bin-fhe, mhe and blas; in ckks the untyped `CKKSError::Internal` (`ckks_ensure!`), or an `anyhow` error in setup, never a typed variant; a reference helper given an override's remainder checks only its budget, and a body whose first effect is a nested call checking its own query, nothing carved before it, needs no check of its own.
- **Checked size arithmetic.** Sizes, counts and offsets from caller dimensions use checked arithmetic (`checked_mul`, `checked_add`, `checked_product`), overflow being a panic in panic crates and allocation and query functions, the error of a fallible ckks or blas operation, or `InvalidData` in readers.
- **Checked key lookups.** Key users call the source's checked getter (`get_automorphism_key(p, k)`, `get_tensor_key(k)`) at the decomposed `k`, `lookup_*` serving only getters, forwarding lookups and layout reads of unused keys, and new key-source traits keep the required `lookup_*`, provided `get_*` split.
- **Key-source errors keep their detail.** Lookup errors reach the caller intact: `unwrap_or_else(|e| panic!("{e}"))` (context prefix optional) in panic crates, the typed missing-key variant with the error as `source` in ckks and blas, never `expect("<literal>")`, `.ok()`, `map_err(|_| ..)` or untyped wraps.
- **One key-coverage refusal.** Panic crates refuse an input wider than a gadget key's `max_input_k` with core's `assert_key_covers` and its message, scheme layers adding no wording of their own, and ckks and blas with their typed variant.
- **One row-offset refusal.** A GGLWE consumer that cannot honour a key's row offset refuses a `k_offset > 0` key before use, in panic crates with core's `assert_no_row_offset("<op>", &key)`.
- **Per-crate error models.** A change keeps its crate's failure model (table), never switching between panic and `Result` or adding an error type.

## 5. Scratch and allocation

- **Scratch operations have queries.** Every public scratch-taking operation has a `*_tmp_bytes` query dispatching to the selected implementation (its own or a documented family query; polynomial-evaluation engines excepted), an `_assign` form sharing its out-of-place sibling's query, the maximum over both, called with `res` as input, unless that sibling takes no scratch or its derived body nests the `_assign` form, the `_assign` form then owning `<stem>_assign_tmp_bytes`.
- **Query parameters.** A query takes, in operand order, one shape argument (limb sizes in hal, layouts or infos above) per operand whose shape changes the carve, source and destination where both can, plus the scalars the body branches on (`cnv_offset`, a hint, a degree, a term or thread count, a plan), never data, a `Source`, scratch or one widest layout for several operands (keys entering as their layouts or a key source read only for them); crate files state exceptions.
- **Scratch is the last parameter.** Scratch comes last as `scratch: &mut ScratchArena<'_, BE>`, except in private helpers with trailing closures or task bodies and the executor helpers (`for_each_chunked`, `for_each_with_scratch`); kernels below the OEP take typed slices carved from it, and sampling methods take no scratch and their source last.
- **Query covers the whole body.** A query is the coexisting temporaries plus the largest nested phase (`lvl_0 + max(nested)`): nested calls at their selected query (HAL ones too, even at 0 on CPU; `*_tmp_bytes_reference` only for reference helpers without an OEP hook and gated-override fallbacks), every layout-allowed branch reserved (a flag-clear input's copy or normalization, radix conversion, gated fallbacks), per-worker scratch multiplied, a temporary scoped out before a nested call counted only in its branch, all from layouts.
- **Round coexisting temporaries.** Each temporary summed with another or with a nested query counts as `BE::scratch_aligned(bytes)` (or `worker_scratch_bytes`, `next_multiple_of(BE::SCRATCH_ALIGN)`).
- **Backend-routed byte counts.** Layout bytes come from the backend (`Backend::bytes_of_*`, `module.bytes_of_*`, `*_bytes_of_from_infos`), never a static `bytes_of` or hard-coded word size; only a crate buffer with no backend-routed size uses its own `bytes_of`.
- **Override body and query together.** An override with different scratch use overrides its `_tmp_bytes` in the same impl, a gated fast path shares predicate and fallback between body and query, and an override may report less than the reference, never less than it takes.
- **Arbitrary scratch, zeroed allocations.** Owned layouts above hal are zeroed and canonical (`Backend::alloc_zeroed_bytes`), scratch (`alloc_bytes`) arbitrary on entry and after every call taking it: a carved temporary is written, backend-zeroed (`vec_znx_zero`, `glwe_zero`, `copy_host_to_view(region, &[])`) or overwritten before any read, with `canonical = false` and no noise or plaintext metadata until set.
- **Fresh objects record no distribution.** Every allocation and carve of an object recording a secret's distribution (secrets, blind-rotation keys) starts at `Distribution::NONE`.
- **Carving idiom.** Carve from a reborrow (`let (tmp, rest) = scratch.borrow().take_*_scratch(..)`), chain on `rest`, pass `&mut rest` (`&mut rest.borrow()` when `rest` is used again) down, reborrow per iteration, end a lifetime with a block or `scratch.scope(|s| ..)` before carving its replacement, and keep `take_region` inside the crate take traits (test probes reserving a guard region excepted).
- **Take method per temporary type.** Carved layouts come from `take_<layout>_scratch` methods of the crate's take trait (`ScratchArenaTakeBasic` and its layers), sized like `*_bytes_of_from_infos`, never from raw HAL takes.
- **Temporaries live in scratch.** Call-local temporaries are carved from scratch and counted; bodies heap-allocate only what the caller keeps (results, prepared objects, plans, caches), per-call view and term lists allocated once and refilled, blas long-lived temporaries, ckks per-call outputs and oracle temporaries, never a temporary `*_alloc_from_infos`, any other per-call heap allocation being a finding even unmeasured.
- **Parallel work and per-worker scratch.** Generic code parallelizes only through `BE::TaskExecutor` (`join`, `for_each`, `for_each_with_scratch`; scoped threads only over validated caller per-worker contexts), reserving `scratch_workers::<BE::TaskExecutor>(cap) * worker_scratch_bytes::<BE>(per_worker)` (`cap`: the backend's worker cap for the kernel family) and splitting at most that many arenas (`scratch_workers_within`, `for_each_chunked`, `split(worker_count::<BE::TaskExecutor>(cap, tasks), per_worker)`), fewer workers for smaller arenas or pools; sizing reads no pool width (`max_parallelism()`, `rayon::current_num_threads()`) unless the caller picks the thread count, query and body then reserving `worker_count::<BE::TaskExecutor>(threads, items)`, as the doc states; a parallel schedule is chosen by the executor (`BE::TaskExecutor::IS_PARALLEL`, read alike by body and query), never by an opt-in macro arm or a flag of its own.
- **Rounded worker shares.** A body splitting its arena per worker passes `split` one share rounded by `worker_scratch_bytes::<BE>(..)`, the share its query reserves per worker.
- **Schedules share one body.** A parallel schedule and its serial branch run one body over the same tasks or stages.

## 6. Module, degree and ring

- **One module, every degree.** A degree-`N` module serves every power-of-two degree from `Backend::MIN_DEGREE` to `N`; computing operations take no degree argument, read degrees from their operands and assert through the crate's check (`check_degree`, `operand_degree`, a typed error) that the module serves them (at most `module.n()`, agreeing as the contract requires), never building or choosing another module; a HAL operation whose `domain` says the module's degree does not enter checks only the degree relations it states.
- **Module-degree crates.** bin-fhe, mhe and blas operands and CKKS ciphertexts are at the module degree: their operations assert it, their allocators take no degree and allocate at or assert `module.n()`, and a smaller degree enters only where the crate file names it (CKKS plaintexts and diagonals, mhe switching-key share secrets).
- **Query and carve degrees.** No query under-reports below the module degree: hal queries take no degree and size at `module.n()`, queries above hal size each temporary at its carve degree (the infos degree, else `module.n()`), and bodies carve at the operand degree (`take_*_scratch(res.n(), ..)`), using `module.n()` only where the domain fixes the module degree.
- **Degree first.** An allocation, byte-count or carving function taking a degree takes it first (`lwe_alloc(n, base2k, k)`, `bytes_of_vec_znx_dft(n, cols, size)`).
- **Galois elements at operand order.** Galois elements use `galois_element(generator, order)` or `galois_elements_from_rotations` at the operand's order `CYCLOTOMIC_ORDER_FACTOR * n` (`module.galois_element(g)` only at degree `N`, `module.cyclotomic_order()` only there or as the modulus of an inverse or composition), rotations first reduced with `rem_euclid` against the slot count.
- **One degree floor.** Floor checks, per-degree tables and degree sweeps derive from `BE::MIN_DEGREE`, never a literal, and sweeps of smaller operands stay at or above it, except a module-independent HAL operation's.
- **Ring degree cap.** `MAX_RING_DEGREE = 2^17` holds on both rings and is checked once, at module construction, with root tables up to order `2^19` (`4N` on the conjugate-invariant ring); code, tables or tests serving only `N > 2^17` are flagged as dead, transforms of size `2N` serving the conjugate-invariant ring at `N = 2^17` (NTT `MAX_LOG_N = 18`) being live.
- **Ring is a compile-time type.** The ring is the sealed `Backend::Ring` (`Standard`, `ConjugateInvariant`), never a runtime switch, ring quantities come from it (`CYCLOTOMIC_ORDER_FACTOR`, never `2N`), and standard-only families bound `Backend<Ring = Standard>` on their OEP trait, directly or through a supertrait, so misuse fails at compile time.
- **Prepared objects never move.** Prepared and DFT objects stay on the backend and ring configuration that made them: other backends prepare the transferred coefficient-domain source, and only operation results are compared (exceptions: `docs/review/hal.md` section 7).
- **Plans cached in the module.** A scheme plan cached across calls lives in the module's `ModulePlanCache` (`ModulePlanCacheProvider`), never in a global cache.

## 7. Layouts, views and memory

- **Owned storage.** Owned containers store `BE::OwnedBuf` (`AlignedBuf` on host), never `Vec<u8>`, taking host bytes through `AlignedBuf::from` or `from_bytes(impl Into<AlignedBuf>)`; host tables or staging buffers needing more than element alignment are `AlignedVec<T>`, never handed to a `Vec`, and a plain `Vec<T>` serves naturally aligned tables.
- **Prepared-object lifecycle.** Prepared and plan-like objects are allocated by `*_alloc_from_infos(infos[, hint])` and sized by `*_bytes_of_from_infos`, both directly on `Module` with no OEP method, and filled by a non-allocating `*_prepare(res, other, scratch)` that rejects a foreign layout before writing, allocating forms being derived defaults.
- **Prepare hints select the representation.** A prepared layout's `PrepareHint` enters every sizing, allocation and carve of it, a byte count or query passing the hint of what it sizes, and changes no bits: an operation over prepared operands gives the same bits under every hint and mix of hints (its unprepared operation's, where one exists), its functional and parity tests running every hint and mix; library code prepares an operand reused across calls or products with `PrepareHint::Reuse`.
- **Refills equal fresh builds.** A preparation or encoding into an existing destination overwrites, without reallocating, everything its source determines, data and metadata, a refill equalling a fresh build.
- **DFT narrowing behind a hook.** Generic code narrowing a `VecZnxDft` to a strict limb range (`with_size_mut`, `with_limb_range_mut`) or calling `zero_at` states `const { assert!(BE::DFT_LIMBS_CONTIGUOUS, ..) }` and isolates that stage in an overridable OEP method with its query, which a backend with another DFT layout overrides.
- **Host transfers through hooks.** Bytes cross between host and backend only through the `Backend` hooks (`from_host_bytes`, `from_bytes`, `to_host_bytes`, `copy_to_host`, `copy_from_host`, `copy_view_to_host`, `copy_host_to_view`), `transfer_buf_into`, `TransferInto` and `to_host_owned`, and generic code zeroes backend storage through backend operations, never host slices.
- **Transfers check shapes and carry metadata.** A `TransferInto` impl asserts every layout parameter and container shape equal between source and destination and copies every metadata field.
- **Host helpers say host.** In backend-generic crates, module operations and test or bench helpers touching host memory carry `host` in their name (`*HostOps`, `alloc_host_*`, `upload_host_*`, `random_host_*`); host-bound layout methods (codecs, serialization, `Debug`) need no marker.
- **Raw pointers from one base.** A kernel caching several raw pointers into one buffer derives them from one base pointer taken once (`base_mut_ptr()` or `raw_mut().as_mut_ptr()`) plus shape offsets (`scalar_offset(col, limb)`) after bounding the farthest, never from a second `at_mut`, `at_mut_ptr` or `as_mut_ptr`.
- **unsafe documents its preconditions.** A `pub unsafe fn` has a `# Safety` listing caller guarantees (target features, slice lengths and alignment, aliasing), and an `unsafe` block relying on a bound checked elsewhere has a one-line `// SAFETY:` naming it, except, inside `#[target_feature]` functions, intrinsic-only blocks and calls of an `unsafe fn` whose contract holds by construction.
- **Send and Sync.** `unsafe impl Send`/`Sync` appear only on exclusive-storage owners (`AlignedVec`, `ScratchArena`, `Module`) and on raw-pointer wrappers whose tasks read only or write disjoint ranges and join before reuse or release, with a comment stating so; storage meets the `Backend` bounds (`OwnedBuf: Send + Sync`, `BufRef<'_>: Sync`, `BufMut<'_>: Send`) with no new unsafe impls on layouts.
- **Bounded Debug.** `Debug` prints shape, infos and counts over opaque storage, with no host-data bound, and at most 16 coefficients per limb per column of host layouts; new layouts get `PartialEq`, `Eq` and such a `Debug`, types holding secret material implement no `Debug` or `Display`, redacting ones included, and types only determining it (`PaCoSecretSpec`) at most a shape-only `Debug`.
- **Infos forwarding is complete.** A forwarding Infos implementation (references, wrappers, newtypes, forwarding macros) forwards every provided method an implementor overrides (`LWEInfos::noise`, `LWEInfos::size`, `GGLWEInfos::stride`).
- **New fields reach every piece.** A field or component added to or changed in a layout or bundle above hal is threaded in the same diff through its `<X>Layout`, its Infos trait and every implementor, raw and prepared allocation, `TransferInto`, `WriterTo`/`ReaderFrom` and preparation.

## 8. Normalization and the canonical flag

Definitions: `# Canonical form` in `poulpy-hal/src/api/mod.rs`; flag rules: `# Canonical flag` in `poulpy-core/src/layouts/glwe.rs`.

- **One flag, on GLWE only.** Only the runtime `canonical` flag of core `GLWE` (and its `GLWEMask`) tracks canonical form; canonical-by-contract layouts (GGLWE, GGSW and their rows, tensors, plaintexts, public keys) get no flag or flag-needing view, and no `Normalized`/`Unnormalized` typestate or `_unnormalized` variant exists.
- **Wrappers forward the flag.** A scheme wrapper of a core GLWE forwards `set_canonical` and `is_canonical` to it, keeping no copy; a flagless-layout wrapper's `set_canonical` is a no-op reporting canonical, and code writing a flag-clearing result into it normalizes first.
- **Manual `set_canonical(true)`.** Legitimate only (a) on the owner after a write leaving every limb canonical (normalizing every limb, or copying a value the body just normalized at the destination's radix and precision), (b) as a deliberate bypass into a tolerant DFT or key-switch reader, or (c) after writing canonical-by-construction data (own-radix uniform fill, seeded mask, canonical LWE limbs, raw copy of a vector canonical by flag or contract, `k`-lowering relabel of a value canonical at the new width), (b) and (c) with a one-line comment right above naming the consumer and the tolerating margin or fact.
- **Raw copies of flag-clear operands.** A non-normalizing limb-wise operation (copy, negation, monomial rotation, automorphism, ring switch) reads a flag-clear operand raw only when the destination holds every source limb, else normalizes, keeping the source flag only under the digit-preserving condition (canonical source, same `base2k`, `res.k >= a.k`).

### 8.1. Delay normalization to the last required boundary

- **Lazy by default.** Accumulations stay unnormalized, flag cleared, while bounds allow, normalized right before the first consumer needing canonical digits or at a canonical output contract; each normalization serves a named requirement (a canonical-input consumer, a specified radix, precision or rounding, a proven headroom limit, a canonical or flagless output), never a mere function return, a per-term pass, canonical-by-construction data or an operation that normalizes its flag-clear input itself.
- **Normalize a shared operand once.** A value read by several canonical-input consumers is normalized once at their latest shared boundary, in place when mutation is authorized, else into one scratch copy (and prepared form, where allowed) they all reuse.
- **Rounding placement is contract.** Normalizations, gadget decompositions and rounding shifts round to their explicit `k`, ties to even (`rnd(x + c, k) = rnd(x, k) + c` only for `c` an even multiple of `2^-k`): moving one across a sum, shift, radix conversion or truncation, or splitting or merging rounded terms, needs a bit-exact argument or is a contract change; lossless normalizations (to the input's full limb width) move freely, and carry and rounding limbs stay until the rounding boundary.
- **Headroom follows the average-case model.** Guard limbs, windows and lazy-sum headroom follow `docs/guides/base2k-failure-probability.md` (failure at most `2^-128`), not the worst case: long lazy sums normalize in place before exceeding the larger of `2^(63 - base2k)` and the Gaussian count of one shared core helper (never re-derived per call site) or at a caller-set cadence documented as a caller obligation, no radix is refused for sum length, two lazy product terms need `base2k <= 62`, and a sum spanning calls (mhe aggregation) leaves headroom to the caller.
- **Normalizer input domain.** Normalization inputs stay in the domain (digits in `[-2^62, 2^62]` for 64-bit words, `|x| <= 2^126` for 128-bit coefficients) and transforms in their exactness bounds, normalizing or batching first where a composition could exceed them.

### 8.2. Minimize DFT and IDFT work

- **Transform each unchanged operand once.** An unchanged operand is transformed once for all compatible uses (counted per operand, column, limb and loop, inside helpers too), prepared operands persist over their reuse interval, prepared-product paths never reconstruct or retransform the originals, and compatible products, sums and automorphisms stay in DFT or BIG form until digits are needed.
- **Hoisted decompositions share one grid.** An input decomposed and transformed once for several key switches serves only keys on one digit grid (whole-limb digits for every key, or one shared `(k_digit, dnum)`), bit-identical with each key's own switch.
- **Convert only what is needed.** Transforms and normalizations cover the actual degree, the needed columns and the live limbs (`ceil(k / base2k)` plus rounding guard and carry limbs), not the allocated buffer, and fewer calls never justify wider transforms or more memory traffic.
- **Finish with the fused inverse.** A composition whose DFT accumulator dies at its inverse finishes each column with one `vec_znx_idft_normalize` at the destination's `k` (addend as column addend, sub-limb offset as `res_offset`), not `vec_znx_idft_apply`, `vec_znx_big_add_small_assign` and `vec_znx_big_normalize`, unless a BIG-domain operation intervenes, one inverse feeds several outputs or the fused operation cannot take the addend (a subtraction).

## 9. Metadata

- **Read first, write on owner.** Input metadata, an in-place operand's included, is read before the first mutation; output metadata the write reads (`k`, `base2k`, rank, a scheme's scale label) is set before the write, and metadata describing the result (canonical flag, noise estimate, distribution, seeds, wrapper fields, batch records) after the last write, both on the owner, never a view.
- **Evaluation outputs are untagged.** Homomorphic evaluation outputs carry no noise estimate (the core contract lists those that do), and where an input copy can reach the output (a copy branch, relabelling or forwarding without writing data) the body clears its estimate with `set_noise(None)`.
- **Prepared noise.** Stored-layout preparations (`*_prepare`: keys, `GLWEPrepared`) keep their source's noise estimate, and prepared product operands (`glwe_prepare_left`, `glwe_prepare_right`, `ckks_prepare_*`) carry none.
- **Output queries match the stamp.** A public output query (an output layout or width, such as `ckks_fold_layout` or `blas_<op>_output_layout`) applies its operation's stamping rule and changes with it in the same diff.

## 10. Sampling, seeds and secrets

- **Draw order is contract.** Per-source draw order and child-seed derivation are documented on the API trait, kept by every implementation and changed only as `**Breaking, behaviour:**` with regenerated golden fixtures.
- **Source parameters.** `Source` parameters come in the order `source_xs` (secret), `source_xu` (ephemeral), `source_xe` (error), `source_xa` (mask), `source_xm` (MHE mask), `source_smudge` (flood), or `source` for a single stream; a seed replacing a source precedes them, named after it (`seed_xa`) or `seed` where its family does (mhe protocols, core compressed GGLWE and public-key forms).
- **Floods on the destination grid.** A `flood: Noise` passes `flood.assert_valid_for(base2k, k)` at its destination's `base2k` and `k` and is added on that grid by `vec_znx_add_noise(base2k, k, ..)` from `source_smudge`, after the destination's normalization at that `k`.
- **Sampled values are per backend.** Cross-backend tests of `SamplingImpl` draws run under the controlled-sampling scope (`ControlledSampling*`), while HAL uniform fills (`vec_znx_fill_uniform_source`, mask fills, compressed masks) match everywhere and compare directly.
- **Encryption parity compares the sources.** Every encryption or key-generation entry of encryption parity also compares each source's post-call state (`source_snapshot`).
- **Sources come from caller seeds.** Library code seeds a `Source` only from a caller-supplied or drawn seed (compressed mask seed, `new_seed()`, `branch()`), never a constant.
- **Child seeds from the root seed.** Child seeds derive from the root seed (`seed`, `seed_xa`) as `Source::new(<root seed>)` then `new_seed()` (or `branch()`, which draws the same seed), a compressed form of several entries or elements drawing one mask seed per entry or element, in entry order.
- **Fixed test seeds per role.** Test sources use fixed literals (`Source::new([x; 32])`) or deterministic helpers (`next_test_seed(tag)`, `new_seed()`), never entropy, one seed per random role and per combined encryption, pooled trials drawing fresh child seeds per role, a seed reused only to replay draws.
- **Carve and wipe secret temporaries.** Top-level secret-reading operations (encryption, key and share generation, decryption, secret preparation and conversion, key generation carving rotated secrets) carve secret-derived temporaries from the caller's scratch, never heap or host, run every refusal before their first secret-derived scratch write, end, once their carves drop, with `scratch.wipe(<its _tmp_bytes>)` (a reference: `<op>_tmp_bytes_reference(..)`) on the arena they received, whatever their callees wipe (a caller carving no secret-derived temporary itself and making a single such call on the same arena inherits its wipe), and are tested by `poulpy_core::test_suite::assert_wipes_scratch` on that budget; a missing secret-side backend operation is added to core or HAL, never staged through host.
- **Randomness obligations of the caller.** Seed distinctness, domain separation and the secret distribution are caller obligations, never enforced.

## 11. Serialization

- **Only ciphertexts and keys serialize.** Above hal, `WriterTo`/`ReaderFrom` exist only for ciphertexts and keys (standard, compressed) and composites of them (shares, grids), never for plaintexts, linear transformations, LUTs, plans, secrets, prepared objects, contexts or public operands, and hal serializes only host coefficient-domain layouts; header and metadata fields are little-endian.
- **Writers require canonical input.** `write_to` of a GLWE or GLWE composite rejects any flag-clear member with `InvalidInput` before its first byte and never normalizes.
- **Readers trust canonical digits.** `read_from` marks flag-carrying values canonical and trusts canonical-by-contract layouts, checking shape and metadata only, never digits or provenance.
- **Failure kinds and untrusted streams.** Serialization returns `std::io::Result`: `InvalidInput` (nothing written) for a value unfit to write, `InvalidData` for a malformed stream or one its receiver cannot hold, never panicking on stream content: header fields pass `try_from`, size products are checked and every header field compared with the receiver before the payload, and metadata is committed after it (per component for a composite read component by component).
- **Format changes are breaking.** A serialized-format change is a `**Breaking, format:**` CHANGELOG entry.

## 12. Naming

- **One stem through the layers.** An operation keeps one name stem across its API trait and method, OEP trait and method, reference, derived body, macro arm, query and family files.
- **Suffix order.** Suffixes stack as `<stem>[_qualifier][_add | _sub | _sub_negate | _into][_assign][_with_plan][_tmp_bytes][<last>]`, `<last>` a layer suffix (`_reference`, `_derived`, `_portable`, `_default`) ISA suffix (`_avx2`, `_avx2_fma`, `_avx512`, `_ifma`, `_neon`) or `_par` (a parallel driver), and only `<last>` follows `_assign`, or `_tmp_bytes` where the `_assign` form has its own query.
- **In place is `_assign`.** In-place mutation ends in `_assign` (except mhe protocol aggregation `mhe_<object>_share_aggregate(res, a)`), a clobbered source being shown by `&mut` and the contract, and no public operation uses `_inplace`, `_in_place`, `_consume` or a trailing `_backend` (view accessors such as `at_backend` are not operations).
- **No `_into`.** Operations, preparations and encoders write `res` under the destination suffixes of table 12.1, `_into` appearing only in the older core and ckks `_into` families (`docs/review/core.md` section 2), new operations taking table 12.1's suffixes.
- **Queries named after operations.** Operation `X`'s query is `X_tmp_bytes`, declared with it (hal: in its own `XTmpBytes` trait), a family query takes the family stem and its doc lists the covered operations, and a per-representation query inserts the path before `_tmp_bytes` (`glwe_eval_linear_transformation_unprepared_rhs_tmp_bytes`).
- **Lifecycle names are object-first.** Outside hal, lifecycle methods are `<object>_alloc[_from_infos]`, `<object>_bytes_of[_from_infos]`, `<object>_prepared_alloc[_from_infos]`, `<object>_prepared_bytes_of[_from_infos]`, `<object>_prepare_tmp_bytes`, `<object>_prepare(res, other, scratch)` and `take_<object>_scratch`; operand preparation keeps operation grammar (`ckks_prepare_left`), and only hal spells `bytes_of_<layout>`.
- **Layout and view names.** A layout `T` has an owned alias in its crate's spelling (`TOwned<BE>`; hal `TOwned<W>` on coefficient layouts and `TOwned<B>` on opaque ones; core `Backend<T><BE>`), `TBackendRef<'a, BE>`, `TBackendMut<'a, BE>`, `TToBackendRef<BE>::to_backend_ref`, `TToBackendMut<BE>::to_backend_mut`, `TLayout` and `TInfos` (or its wrapped layout's); new layouts use exactly these suffixes.
- **Tier names.** In every crate, an object `T` keeps the bare name for its unprepared form (coefficient-domain, encoded, read streamed), its seeded form being `TCompressed` and its prepared form `TPrepared` with `TPreparedFactory<BE>`, never `TUnprepared` or a bare name for the prepared form.
- **Layout generics.** A coefficient layout above hal is `X<D: Data, W: ZnxWord>`, any scheme parameter (an algorithm marker, an integer type, a ring) coming after `D`.
- **Galois-element queries.** Galois-element queries are `<op>_galois_elements` returning `Vec<i64>`, crate-prefixed at module level (`glwe_trace_galois_elements`), unprefixed on plans and layout functions, and bare `galois_elements` on single-operation plans, layouts or contexts, a module-level query taking the operand degree `n: Degree` first and listing elements at that degree's order, a plan, layout or context reading its own degree or, holding none, taking `cyclotomic_order` first.
- **Macro names.** A new macro is named by kind: opt-in and umbrella macros by table 12.1, suite macros `<crate>_<kind>_test_suite!` (hal: `backend_test_suite!`, `cross_backend_test_suite!`).
- **Reference layer is never `default`.** The reproduced implementation is named `reference` (module, `*Reference`, `*_reference`, `impl_*_reference*!`); `default`/`Default` names only poulpy-cpu-portable's `hal_defaults` traits and `impl_cpu_<scheme>_defaults!` macros and `std::default::Default`, fallbacks being `oep::derived` bodies.
- **Reserved parameter names.** Workspace identifiers keep their meaning (section 12.2), `n` never being a count; operand properties are `<operand>_<property>` (`res_k`, `a_base2k`), derived precisions `k_<what>` (`k_digit`, `k_offset`), and only rotation and automorphism exponents are named `k` or `p`; an automorphism-key source is `keys`, a tensor key `tsk`.
- **Argument order.** After `&self` (`module` in reference functions and kernels) come op-wide scalars (`cnv_offset`, a rotation or automorphism exponent the call applies, `threads`, scheme scalars), `res` and its qualifiers, the mutated operand always coming first (decryption's plaintext included; sources and `scratch` keep their places), each operand with its qualifiers and selectors, plans, contexts and matrices, the tensor key, automorphism keys, other keys, noise laws and `flood`, sources, then `scratch`; key generation and encryption keep their key parameters (`p`, `sk`) after `res`, and crate files fix orders only within these groups; a container's convenience method takes `module` right after `&self`, then its API method's remaining arguments in that method's order.
- **Follow the closest neighbour.** Where table 12.1 leaves a choice, a new method copies its closest same-family neighbour that follows it exactly (suffix, parameter names and order, query arguments); harmonizing a family is a separate complete rename.
- **A rename is complete.** A rename moves the API and `TmpBytes` traits, query, OEP, `_reference` and `_derived` forms, macro arms, `paste!` fragments, tests, bench runner and `BenchOp` name, HAL contract `op` and `test` lines and doc mentions (globs included) together and leaves no old-stem hit outside `tools/poulpy-bench/old_benches/`.
- **Banned and misspelled names.** A plaintext is "of degree `n` dividing `N`" or "of `slots` slots", never "compact", "sparse", "full" or "below the ring" (other senses keep their words: compressed keys, packed CRT words, narrowed ciphertexts, `log_sparsity`, sparse secrets, bin-fhe accumulators), a smaller-degree HAL operand is a degree embedding (`embed`), and identifiers are spelled right, copying no typo (`glwe_blind_retrieval_statefull`, `identity_codgen`, `executebdd_*`).
- **The mhe grammar stays local.** The `mhe_<object>_share_<op>` grammar applies only inside poulpy-mhe.

### 12.2. Glossary

- **`n`, `N`.** `n` (`Degree`) is an operand degree or LWE dimension, `N` the call or module degree.
- **`base2k`, `k`, `size`.** The radix in bits per limb (`Base2K`, a call parameter in hal, a layout property above it), the torus precision in bits (`TorusPrecision`) and a limb count, `ceil(k / base2k)` limbs being live (an allocation may hold more).
- **digit, `k_digit`, `dsize`.** A balanced base-`2^base2k` limb value; gadget digits span `k_digit` bits, not necessarily whole limbs, `dsize = ceil(k_digit / base2k)` being derived, never stored.
- **`col`, `rank`, `dnum`.** One polynomial of a vector layout, `cols` counting them (matrices: `rows`, `cols_in`, `cols_out`); the mask polynomial count (a GLWE has `rank + 1` columns); the gadget digit count, a gadget layout's rows.
- **`max_input_k`.** The widest input precision a GGLWE key decomposes exactly (`GGLWELayout::max_input_k`).
- **degree embedding, window.** Reading a degree-`n` operand at a call degree `N` it divides (HAL `embed` line); a view of a sub-range of a `VecZnx` or `VecZnxBig`.
- **flag-clear, lazy.** A GLWE whose canonical flag is false; a result kept flag-clear until a consumer needs canonical digits.
- **prepared, compressed.** The opaque backend product form of an operand or key, valid on its backend and ring only; a layout storing its mask's 32-byte seed.
- **PAT, share, flood.** A public aggregatable transcript, seeded or not, that mhe parties generate, aggregate and finalize; a protocol type wrapping PATs or core layouts plus result metadata; caller-sized smudging noise (`flood: Noise`).
- **OEP.** The `unsafe` traits through which a backend implements or overrides operations.
- **basis operation.** A HAL operation of class `basis`, independently defined by its contract block, a required OEP method without default body; a `variant`, required unless it only re-views its operand as another layout (then `derived`), is another storage or mutation form of a defined op.
- **parity, attestation, oracle.** Identical results of an implementation and a comparison backend on identical inputs; passing parity against an attested backend, for the operations and ranges tested, transitively from the oracle (poulpy-cpu-oracle), the independent plain-loop root.
- **Rayon twin.** A backend type running a serial base type on Rayon, returning exactly its base's words.
- **lane.** A CI job configuration: features, target flags, filters, native or emulated.

## 13. Documentation and comments

- **Docs describe the current code.** Docs, specs included, describe current code, with no future-work promise ("for now"), plan-phase label ("Phase 1") or removed or nonexistent item, history going to the CHANGELOG (rustdoc names a former behaviour only where callers need the contrast).
- **Docs move with the code.** A diff changing a documented item, behaviour, contract, convention, registration list or number updates in the same diff every doc stating it (rustdoc, contract blocks, `poulpy-*/docs/*-contracts.md`, `docs/`, READMEs, `CONTRIBUTING.md`, CHANGELOG test names), old names grepped in glob and prose forms, and docs show no command that cannot run and no item a later PR adds.
- **Self-contained docs.** Comments, rustdoc and contract docs cite no issue or PR number, spec section or ruling label (papers allowed); issue links live only in the CHANGELOG and PR descriptions.
- **Docs never let overrides diverge.** Docs present overrides as bit-exact routes to the reference result, metadata, mutation and failures included, free only in kernels, prepared form, scratch size and seeded sampler values, and attestation as transitive parity, naming no fixed backend chain.
- **Public items document their contract.** A new public API trait or method documents its result (formula where one exists), mutation, metadata effects, failures (panics under `# Panics`, errors under `# Errors`; hal's api: its one sentence) and path exactness, shared points on the trait; `_tmp_bytes` and `bytes_of_*` queries carry a doc only when it adds to the name, except in hal's api (one sentence each) and blas (`# Panics`).
- **Refusal docs state the write point.** Above hal, a public operation's `# Panics` or `# Errors` states whether `res` stays untouched on refusal.
- **Reference items name their contract.** A new public `*Reference` trait or `*_reference` function links the OEP family or API method it implements and names any opt-in macro forwarding to it, never calling a reference "portable".
- **A concept is documented once.** A notation, metadata rule, protocol or invariant is documented once, on its owner or, across families, in the crate contracts doc, methods adding only their specifics; delegates, OEP mirrors, call sites and `pub use` re-exports carry no copy, a statement found only on a re-export moving to the item.
- **Contract docs hold shared rules.** Cross-implementation rules other than the layering model live once in `poulpy-<crate>/docs/<crate>-contracts.md` (hal: `poulpy-hal/docs/backend_safety_contract.md`, `poulpy_hal::api` module docs), per-operation contracts on API methods and per-family obligations in OEP `# Safety`; a diff changing a cross-cutting rule (a family, an opt-in or umbrella macro, a scratch or validation convention, a test registration rule) updates that file, which the crate README links.
- **Caller obligations are documented.** Each unchecked caller obligation (numeric bounds and headroom, seed distinctness and domain separation, secret distribution, key provenance in caller-supplied key bundles, trusted serialized input) is documented as the caller's on the item concerned.
- **Crate and module role docs.** Each crate root has a `//!` doc (what it is, layer dispatch, contracts doc location), and each public root module a `//!` or `///` doc, `api`, `oep`, `reference` and `test_suite` submodules excepted when their items carry the docs.
- **Intra-doc links.** Public docs link no private or `pub(crate)` item (reference module: ``[`reference`](mod@crate::reference)``) and cite repository markdown by code-span path or absolute GitHub URL, never a relative link; a new library crate joins, in the diff adding it, the `-p` list of the portable lane's `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps` step, and unlisted crates (poulpy-hal, poulpy-bench, `poulpy-cpu-*`) are checked by hand.
- **Doc examples.** Library and poulpy-bench doc examples are `BE`-generic doctests or `ignore` fragments (always when naming a backend type), non-Rust blocks fenced `text`.
- **Documented bench commands run.** A documented bench command targets a backend crate (`cargo bench -p poulpy-cpu-<x>`) with every `required-features` and target feature it needs, never `cargo bench -p poulpy-bench` or `*-bench` features.
- **Comments state a non-obvious why.** Comments state only a non-obvious why (deliberate bypass, subtle rounding, pinned edge case, bound-sized parameter), in one line where possible, never narrating code or restating names; hal's one sentence per api method stays.
- **No TODO or dead text.** New code has no `TODO`, `FIXME`, `XXX` or `HACK` and no commented-out code; known limitations are stated as facts in docs.
- **No em dash.** Added or edited text, commit messages and PR descriptions included, has no em dash (U+2014).
- **Lint suppressions.** Suppressions sit on the narrowest item where the lint fires, as `#[expect(lint, reason = "...")]` or `#[allow(lint)]`, the latter required where it fires only under some features, targets or expansions; only `clippy::too_many_arguments` may also be allowed module-wide or for a kernel crate, and no suppression sits where its lint cannot fire (`too_many_arguments` up to seven parameters, `self` included; `private_bounds` once the bound trait is public).

## 14. Visibility, features and API surface

- **Public by contract.** `*Reference` traits, `*_reference` functions and their `_tmp_bytes_reference`, `#[macro_export]` expansion targets (`#[doc(hidden)]` if not API), user-facing entry points (module factories, planning and key-use queries, approximation helpers) and helper traits in public bounds (documented as blanket-implemented, `private_bounds` never silenced) stay `pub` without workspace callers.
- **`doc(hidden)` marks plumbing only.** `#[doc(hidden)] pub` marks only plumbing that macro expansions, override fallbacks or sibling crates reach (`__private` re-exports, the poulpy-cpu-portable plumbing of `docs/review/backends.md` section 12, documented as carrying no stability promise), never crate-internal items.
- **Public derived bodies.** Only hal exposes derived bodies, as `#[doc(hidden)] pub fn <op>_derived` with `<op>_tmp_bytes_derived` in the public `oep::derived`, re-exported from `oep`; above hal they stay `pub(crate)`.
- **One public path per item.** A new per-family file under `api`, `oep` or `layouts` copies its parent's export style, adding no `pub mod` where the parent re-exports private modules (`mod x; pub use x::*;`).
- **Exported macros use absolute paths.** A `#[macro_export]` macro uses `$crate::..` for its crate, `::poulpy_<crate>::..` for others and `$crate::__private::<dep>` (a `#[doc(hidden)] pub mod __private`) for dependencies the invoker may lack.
- **Containers keep their fields private.** Types holding storage or its metadata (ciphertexts, keys, plaintexts, shares, prepared objects, LUTs, plans) keep fields private or `pub(crate)` behind accessors and layout traits (`*Infos`, `*ToBackendRef`, `*ToBackendMut`, `data()`, `data_mut()`); only plain descriptors (`*Layout`, parameter and option records) and invariant-free bundles have `pub` fields, bundles with optional parts, Galois sets or other cross-part invariants keeping them `pub(crate)` behind a constructor and part accessors.
- **Public allocation takes the module.** In core and the scheme crates, module-less host allocators (`T::alloc(..)`, `T::alloc_from_infos(infos)`) are `pub(crate)`, public allocation taking the module.
- **Library APIs need no features.** hal, core and the scheme crates expose their whole API featureless (only `test-utils`, `libquadmath` and the inert `enable-core`, `enable-bin-fhe`), selection features (`enable-<isa>`, `enable-<scheme>`, `enable-rayon`, `enable-test-suite`) living only in `poulpy-cpu-*`.
- **Feature names and gates.** Layer and ISA features are `enable-<layer|isa>`, implying needed layers (`enable-blas = ["dep:poulpy-blas", "enable-ckks"]`); every feature gates something in its own crate unless a `Cargo.toml` comment says compatibility-only, and a new one enters its crate's feature docs in the same diff.
- **Test-only items stay in test suites.** A type, trait impl or helper whose only callers are tests, test suites, benches or examples (a pairing of key sources, a counting or refusing key source, an operand adapter) lives in the owning crate's `test_suite` or in the test, never in a library module; a new library item needs a library caller, named by the PR.
- **Test-only features come from dev-dependencies.** `test-utils` (ckks, blas) and `enable-test-suite` (cpu-portable) are enabled only from `[dev-dependencies]` or other test features (poulpy-bench and the CI doc step excepted), and suite-only code compiles only under them (`#[cfg(feature = "test-utils")] pub mod test_suite`, `#[cfg_attr(not(feature = "test-utils"), allow(dead_code))]` on production items only gated suites use), while hal, core, bin-fhe and mhe export `test_suite` ungated; library code uses no test-suite item.

## 15. Tests

- **Suites live in owning crates.** Library-operation tests are backend-generic `pub fn test_*` in the owning crate's `src/test_suite` (portable kernel traits: `backends/poulpy-cpu-portable/src/test_suite`), which backends instantiate through registration macros or a thin `#[test]`, never a per-backend copy; a backend's own kernel or scheduling tests stay in it.
- **Host code gets unit tests.** New host-only library code (helpers, setup math, map builders, layout queries) gets a `#[cfg(test)] mod tests` of its own.
- **Unregistered suite tests are dead.** Every suite test is reachable from a registration: a new one joins every list that instantiates it (the crate macro or each backend's registration list).
- **Model suites and parity suites.** A new operation has a functional test against its model, not the reference, its functional suite (`<crate>_backend_test_suite!`) registered at least on the oracle and poulpy-cpu-portable's serial types, any backend free to run it on its own types (the conjugate-invariant suites, comparing a CI form with its standard sibling, run on every CI form), and parity registrations on every backend type implementing it (bit-exact unless tolerance is contracted); a reference change needs both.
- **Parity compares values and metadata.** Parity uploads identical fixtures, prepares independently on each backend and compares canonical coefficients, metadata and flag after explicit transfer (DFT results after inverse and normalization, prepared operands through outputs, never opaque bytes), reference outputs first asserted untagged (copy-like outputs keeping an estimate excluded explicitly).
- **The tested backend stays opaque.** Parity helpers bound the tested backend only by API and transfer traits (`CopyToHost`, `CopyFromHost`, `HostStaged`, `TransferInto`), host bounds staying on the comparison side or host copies, definition checks and the core noise and mhe suites excepted.
- **Comparison generics.** Two-backend tests name the backends `BR` (reference) then `BT` (tested), their modules `module_ref` and `module_test`.
- **Coverage narrows, never switches off.** A narrower backend restricts the sweep through the suite's shapes argument (`ParityShapes` or equivalent) or registers a documented subset, never dropping suites or entries.
- **Exact per-implementation budgets.** Each implementation runs the call under test on exactly its own query's bytes (an operation without one: the bound its crate file names) poisoned with `0xA5` (`poisoned_scratch`, `with_scratch`), never a shared or maximum budget, and once one byte below the smallest budget it accepts (its query; for a parallel kernel, one worker's share `fixed + per_worker`), expecting its entry check's panic or error, a refusal test of a check placed before the scratch check running on a zero-byte arena; setup may share one arena sized from its queries, never a constant like `1 << 22`.
- **Invariant checks in shared helpers.** Checks every output must pass (flag honesty, canonical at `k`, refusal one bit past the key) live in the decrypt, measure or verify helper ending every per-op test, never a dedicated sweep, and no per-op test bypasses that helper.
- **Checks come with firing tests.** Each new or changed rejection has a firing case, in the owning crate's functional suite for a body every backend shares and in each overriding backend's registration otherwise, the check comparing against an independent quantity (another operand, `k`, the module, the key layout), and a per-entry check over a `HashMap` is tested with the offending entry at every position.
- **Variants against their definition.** A variant defined through another form (`_assign`, `_zero`, `_with_mask`, prepared against unprepared, fused or summed against composed) is checked bit for bit against it on the same backend.
- **One-term sums.** A summed form is also tested at one term against the single operation its contract names, bit for bit.
- **No accidental passes.** Compared outputs start from content other than the expected result (fixture, poison, dirty fill), never two fresh zero allocations.
- **Every path is reached.** Tests reach every algorithm path and runtime branch (fast path and fallback, lazy and normalized routes, specializations), new reference branches coming with their case.
- **Panic tests pin the message.** In core, ckks, bin-fhe, mhe and blas a rejection test pins the full static message, or the string all implementations share (core "wider than the key's max_input_k"), with `#[should_panic(expected = "..")]` (on a suite's registration line) or `catch_unwind` plus the crate's payload helper reading `&str` and `String` (`panic_message`), never a bare `#[should_panic]`, `is_err()` (ckks parity drivers excepted) or ambiguous fragment.
- **Rejection tests check no writes.** A refused-call test asserts destination data and metadata, `&mut` inputs and sampling sources unchanged, matching ckks and blas typed variants and their `op` (untyped `Internal` by message substring), not `Display` text; a `should_panic` test that does not catch, check the state and `std::panic::resume_unwind` suits only refusals with nothing to compare (a query's or pure helper's check).
- **Mutation boundaries are pinned.** An input borrowed as `&T` is compared with a pre-call snapshot (`to_owned_deep()`, a copy or a digest), and untouched columns, limbs and padding keep sentinels.
- **Off-limb digit widths.** Gadget digit-width sweeps include, besides multiples of `base2k`, a sub-limb width, one bit past a limb and one bit short of two limbs (`ParityShapes::k_digits`, `key_layout_bits`).
- **Test keys cover their inputs.** A test's gadget keys cover the widest input precision the test switches with them.
- **Fixtures sampled on the backend.** Uniform random fixtures come from a backend sampler (`vec_znx_fill_uniform_source`, `fill_glwe_from_source`) on the tested side or, cross-backend, the reference side, host-built only for known values or bounded digits, and round trips read into a receiver holding other content (`test_reader_writer_interface` with independent fixtures, or a fresh allocation), never a copy.
- **Sum tests use independent encryptions.** A lazy-sum headroom or long-sum test sums one fresh encryption per term (`ckks_encrypt`), never copies of one ciphertext.
- **Golden fixtures change on purpose.** Golden values (core public-key digests, CKKS `determinism.txt`) change only with a stated intended change of sampler, draw order or circuit, format (`**Breaking, format:**`), encoding or setup math: CKKS via `POULPY_UPDATE_FIXTURES=1`, then passing on every backend without it, core digests edited in every attesting crate.
- **No whole-buffer dumps.** Layouts compare with `assert_eq!` through `PartialEq` and bounded `Debug`, raw or opaque bytes (`raw()`, `to_host_bytes`, streams, `.data`) only with `assert!(a == b, "<static message>")`, and a snapshot type compared with `assert_eq!` prints lengths, not bytes.
- **Alignment and heap layout.** Tests never carry one allocation's alignment to another (`clone()`, `to_vec()`, `from_bytes(v.clone())` reallocate), using `alloc_aligned` and a bounded off-grid `vec!` search for the two legs, and never depend on heap layout or thread interleaving.
- **Heap-bound tests own a binary.** A heap-bounding test is alone in its `tests/<name>.rs` binary with a counting `#[global_allocator]`, a `[[test]]` entry and its features, and asserts growth relative to entry.
- **Ignored tests.** `#[ignore = "<reason>"]` serves only diagnostics, timings, regenerators and full-size or exhaustive runs, exhaustive checks keep an enabled fast representative, and performance comparisons are benches, never test timing loops.
- **Test names.** Generic tests are `pub fn test_<op>[_qualifier]`, `<op>` the API method exercised (`test_<op>_derived`, `test_<op>_parity` where used, rejections `test_<op>_rejects_<case>`), and helpers carry no `test_` prefix.

## 16. CI

- **Green means the aggregate passed.** A PR is green only when `build-and-test` in `.github/workflows/ci.yml` passed, never on a local subset.
- **No CI for stacked PRs.** A PR not based on main is verified only by retargeting to main or by a passed `workflow_dispatch` run on its head commit, never by its base's run.
- **Map configurations to lanes.** Every cfg-, feature- or target-specific change is compiled and tested by a lane of ci.yml or `.github/scripts/test-backend.sh`, or the PR states its verification (exact command, SDE run, `neon_hal` dispatch).
- **Filtered lanes select by name.** AVX-512 and emulated runs execute only lib tests whose full path holds a test-backend.sh filter token (NEON QEMU keeps its own list), so tests meant for them carry an existing token (list: `docs/review/backends.md` section 13.7) or extend the list, and every filter or skip entry matches.
- **Renames move the CI references.** Renaming or moving a test, module, suite function, registration module or crate path named in ci.yml or test-backend.sh (filters, `--skip`, exact names, `determinism`) updates them in the same commit.
- **Exact-name steps are guarded.** New exact-name steps (`-- --exact`) first assert their expected count from `-- --list` (`grep -Ec '<names>' | grep -qx <N>`, as the binary128 steps do), updated with every rename, addition or removal.
- **Kernel suites in base filters.** Suites of kernels every backend implements (HAL families, normalization, word compatibility, transfers, HAL conjugate-invariant products) sit in the filter list native AVX-512 and emulated runs share, native-only entries being scheme-level and large-ring suites.
- **Emulated runs fit their budget.** An emulated test fits its budget (`bounded_emulation_params`, a cheaper body, or a large-ring name an emulated skip excludes, never a relabelled small test), its emulated cost (local SDE, four cores, two test threads, times about seven) stated in the PR; over-budget lanes get a raised budget, never a `POULPY_TEST_EMULATED` branch.
- **Budget changes update everywhere.** A budget change edits together `execution_seconds` in test-backend.sh, the step `timeout-minutes` (budget plus about two minutes), the job `timeout-minutes` and its comment, and the script comment explaining a raise.
- **One binary for all stages.** test-backend.sh derives features from backend and mode only, so every stage and test group of a job shares one binary.
- **Wiring new jobs and features.** New ci.yml jobs join `build-and-test`'s `needs` with a result check (conditional ones like `neon_hal`: success if requested, else `skipped`), new test-backend.sh groups the `case "$group"` whitelist with filter, budget and step (`timeout-minutes`, mode `if:`), and new gated features join, in the same diff, their lane's `*_FEATURES`, the AVX per-mode features when AVX lanes must test them and the README feature list.
- **Test steps follow lane conventions.** New test steps run `cargo test --profile ci` with the lane's `*_FEATURES` or per-mode features, x86 backend steps through test-backend.sh, only the macOS smoke jobs using the plain profile.
- **ISA flags are target-scoped.** SDE-capable Linux jobs put ISA flags only in `CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_RUSTFLAGS` and `RUSTDOCFLAGS` with `CARGO_BUILD_TARGET` pinned (a global `RUSTFLAGS` only on always-native ISA hosts), changed flags, LLVM-implied ones included, staying covered by native detection and the SDE CPU model.
- **SDE pin moves with checksum.** `SDE_ARCHIVE`, `SDE_URL` and `SDE_SHA256` change together, and every SDE install keeps `sha256sum --check` before extracting.
- **One pinned toolchain.** The nightly pin changes in one commit in `rust-toolchain.toml` and the `RUST_TOOLCHAIN` of ci.yml and release.yml, keeping every `#![feature(..)]`, clippy, rustfmt (`rustfmt.toml` options) and Miri, and cargo jobs install `${{ env.RUST_TOOLCHAIN }}`.
- **Encoding fixtures run by token.** CKKS encoding and setup-constant fixture tests carry the `determinism` token (portable libquadmath step, macOS jobs, native AVX-512 filters), and platform-dependent math changes (a `Quad` backing, a target `cfg`) name their covering job.
- **Workflow permissions stay minimal.** Workflows default to `permissions: contents: read` with writes only where needed (release `id-token: write`; claude job: pull requests, issues, `id-token`), the claude workflow is gated on an `@claude` mention by an OWNER, MEMBER or COLLABORATOR, and publishing uses crates.io trusted publishing (`release` environment).
- **Code-scanning alerts are fixed.** CodeQL alerts are fixed in the PR, never dismissed by argument.

## 17. Process

- **CHANGELOG coverage and placement.** The PR making a user-visible change (public suites, registration macros and test names out-of-tree backends call, contract keys, `#![feature(..)]` gates, user docs, regenerated fixtures) adds an `## [Unreleased]` entry in each affected crate's section (``### `poulpy-<crate>` ``, `### CPU backends` for every `poulpy-cpu-*` crate and the oracle, `### Dependencies`); CI-only changes need none and released sections stay untouched.
- **CHANGELOG prefixes.** An entry opens with at most one of these bold prefixes: `**Breaking:**` (compile or implementation break), `**Breaking, behaviour:**` (new outputs, bits or panics for valid inputs), `**Breaking, format:**` (old data unreadable), `**Behaviour:**` (observable, no valid use broken), `**Fix:**` (now meets its documented contract, even if outputs change), `**Fix, soundness:**` (UB, memory safety); none for compatible additions, a mostly additive bullet putting its breaking part on a `**Breaking:**` continuation line, and an entry fitting several taking the first of this list that applies.
- **CHANGELOG sentences.** Arithmetic changes say whether results change, and performance or precision claims give the figure and parameters.
- **Breaking entries are migration notes.** A Breaking entry maps each removed, renamed, moved or re-signatured public item to its replacement and the caller's or out-of-tree backend's action; an OEP family change names the family, its added or changed methods (required or defaulted), new supertraits or bounds, the reference hand-written impls forward to and, by name, newly registered suite tests.
- **Edit unreleased items in place.** Changes to an item introduced in the current `[Unreleased]` cycle edit its entry to the final state, with no new `**Breaking:**` or `**Fix:**` bullet; stacked PRs describe their own final state, never a later PR's.
- **Deprecations.** Deprecated aliases exist only for released items, beside the replacement under the same gate with `#[deprecated(note = "...")]` naming the replacement or action, re-exports in `#[allow(deprecated)]`, the CHANGELOG naming old and new.
- **Performance claims cite a bench.** Speed claims (fused kernels or overrides, their removal, gate thresholds, algorithm choices) cite a poulpy-bench measurement (Criterion ids `<backend>/<layer>/<op>/<params>`, backend, machine, patch-to-base ratio), adding a sweep row under a new id, existing ids unchanged, when none covers the claim.
- **Commit messages.** One header line `<area>[, <area>]: <what changed>` (`hal, blas: max_base2k returns usize`), with no body, bullets or trailer (never `Co-Authored-By`), `<area>` being a crate name without `poulpy-`, `cpu` for several backend crates, `ci`, `changelog` or `tests`.
- **Never-committed paths.** No diff adds specs, plans, PR drafts, review ledgers or workflow scaffolding (`docs/superpowers/**`, `.superpowers/**`) or ignored locals (`.worktrees/`, `*.patch`, `/ci-local.md`, `.codex`); `docs/spec/` documents shipped code.
- **PR scope.** A PR covers one concern and says "closes #N" only when it completes the issue, otherwise "part of #N".
- **Adding a workspace crate.** A new crate's PR adds root `members` (`default-members` for scheme crates) and `[workspace.dependencies]` entries, the README crate list, dependency tree and (if published) installation entries, a ``### `poulpy-<name>` `` CHANGELOG section, backend `enable-<name>` wiring when backends implement it and a `docs/README.md` contracts link.
- **Release commit and tag.** A release PR bumps all crate and workspace dependency versions, refreshes `Cargo.lock`, cuts `## [Unreleased]` into `## [x.y.z] - YYYY-MM-DD` under a fresh `## [Unreleased]`, records `### Dependencies` bumps, updates README versions and drops never-shipped deprecated aliases; its merge is tagged `vx.y.z`.
