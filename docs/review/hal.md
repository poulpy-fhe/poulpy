# poulpy-hal review rules

Read with `docs/review/REVIEW.md`; this file adds the rules specific to `poulpy-hal`.

## 1. Layering and the op classes

Generic rules: `docs/review/workspace.md` sections 2 and 3.

- **No hal reference layer.** A new basis or variant op gets a portable kernel (`hal_defaults`, `hal_impl_*!`) and an independent poulpy-cpu-oracle implementation calling no portable kernel; poulpy-hal adds no `reference` module, `*_reference` function or reference macro.
- **Four op classes.** Every API method has one class fixing its OEP form:
  - `basis`: independently defined, required, no default body, tested across backends (samplers and the raw complex transform against their definitions);
  - `variant`: another storage or mutation form of a defined op (`_assign`, `ScalarZnx`, conjugate-invariant), required;
  - `derived`: a composition within its signature's scratch, defaulted over `oep::derived`;
  - `support`: allocation, `bytes_of_*`, `_tmp_bytes`, scratch, plans, module queries, no arithmetic.
- **Default bodies follow the class.** Only `derived` ops, their `_tmp_bytes` and `HalModuleImpl::synchronize` have default bodies; adding or removing one updates the op's `class`, `fallback`, `override` and `test` lines in the same PR.
- **What a new op needs.** Beyond `docs/review/workspace.md` section 3: a contract block, a portable binding and oracle implementation when required, a CI filter token for a new test prefix and, for a new family, the `poulpy-hal/src/oep/mod.rs` composition graph and an `unsafe impl` per backend.

## 2. API traits, naming and signatures

- **One op per trait.** A new op is one API trait with one method, its CamelCase with layout acronyms (`VecZnxCIEmbed`), its query an `<Op>TmpBytes` trait, grouped traits excepted: convolution ops join `Convolution<BE>` (each query right before its op), DFT automorphism forms `VecZnxDftAutomorphism`, left and right prepared-operand forms share one trait; support traits are `<Layout>Alloc`, `<Layout>BytesOf` or object plus method (`ModuleN`).
- **Backend parameter only when used.** An API trait takes a backend type parameter only when its signature names a backend type, never on `_tmp_bytes` or `bytes_of_*` traits (spelling: `docs/review/workspace.md` section 12).
- **Declared where the checker sees.** An API trait is a plain `pub trait Name` at column 0 of a file under `poulpy-hal/src/api`, not macro-generated, `pub(crate)`, `pub unsafe` or cfg-gated, with methods `fn` or `unsafe fn` indented exactly four spaces.
- **Operands are backend views.** API and OEP methods take layout operands as `&XBackendRef<'_, B>` or `&mut XBackendMut<'_, B>` (`R: XToBackendMut<B>` for a whole destination), never the host `XOwned<W>`, `XRef` or `XMut` aliases (`VecZnxOwned<W>`, `VmpPMatRef`), and only `NegacyclicFFT` takes host slices.
- **Radix and precision are arguments.** Ops that read digits take `base2k` (and `k` where they round) as parameters; HAL layouts carry no radix, precision or canonical flag (`docs/review/workspace.md` section 8).
- **Degree first on allocation calls.** Functions with no polynomial operand to read a degree from (`<layout>_alloc`, `bytes_of_<layout>`, `Backend::bytes_of_<layout>`, `take_<layout>_scratch`, plan constructors, `Module::max_base2k`) take `n` first, then `rows, cols_in, cols_out, size` (matrices) or `cols, size` (vectors), then the `PrepareHint` of a prepared layout (`docs/review/workspace.md` section 6).
- **Op names.** A ring-arithmetic op is `<family>_<verb>[_qualifier]` with its layout prefix (`vec_znx_`, `vec_znx_big_`, `vec_znx_dft_`, `vec_znx_idft_`, `svp_`, `vmp_`, `cnv_`, `scalar_znx_`, `mat_znx_`), its suffixes keeping their meaning (`_assign`, `_add`, `_sub` and banned suffixes: `docs/review/workspace.md` section 12):
  - `_sub_negate_assign`: `res = a - old(res)`; `_apply*`: transforms and products; `_prepare`: builds a prepared layout; `_with_plan`: takes a plan; `_sum`: sums a term list; `_source`: draws from a `Source`; `_small*`: a big op's coefficient operand;
  - support methods are named after what they return (`n`, `available`);
  - a clobbered source is `&mut`, with `a[a_col] is unspecified afterwards` in its sentence and definition.
- **Argument order.** A new method copies its closest sibling (`docs/review/workspace.md` section 12):
  - normalization `(res, res_base2k, res_k, res_offset, res_col, a, a_base2k, a_col, scratch)`, in place `(base2k, k, a_offset, a, a_col, scratch)`; shifts `(base2k, k, res, res_col, a, a_col, scratch)`;
  - ring maps `(p, res, res_col, a, a_col)`; binary column ops `(res, res_col, a, a_col, b, b_col)`; DFT limb selection `(step, offset, res, res_col, a, a_col)`;
  - convolutions `(cnv_offset, res, res_col, a, a_col, b, b_col, b_coeff | b_galois, scratch)`; VMP `(res, a, pmat, limb_offset, scratch)`, row selection `(res, a, first_row, row_step)`; samplers `(base2k, k, res, res_col, source)`;
  - outside VMP, op-wide parameters first, a one-operand selector (`res_limb`, `res_coeff`, `b_coeff`, `b_galois`) after that operand's column, shared column selectors after their operands (`cnv_pairwise_apply_dft(cnv_offset, res, res_col, a, b, i, j, scratch)`), `scratch` or a sampler's `source` last.
- **Queries take limb counts.** A HAL `_tmp_bytes` takes `module`, the family's leading parameter (`cnv_offset`) and `usize` sizes named after their operand (`res_size`, `b_rows`), keeping its siblings' list even where its default ignores one, and never a degree, layout, infos or view; a shape-independent query takes none and its `ensures` says "independently of operand limb counts" (`docs/review/workspace.md` sections 5 and 6).
- **Plan-based ops.** Plan-based ops follow `VecZnxDftAutomorphismPlan`: an `<Op>Plan` supertrait with `Plan` and `<op>_plan(n, ..)`, a `Send + Sync` plan type in the OEP family, `plan: &Self::Plan` first in `_with_plan` forms, and a derived plan-free form (build, apply, drop).
- **Sampler signatures and draws.** A sampler takes `source: &mut Source` last, its delegate passing one `source.new_seed()` to the scratch-free OEP method without `_source`, its definition `draw(reseed(source), ..)` by limb then coefficient, never by column, stating how far `source` advances, and its multi-column form derived, one seed per column in order (`docs/review/workspace.md` section 10).

## 3. Contract blocks

### 3.1. Grammar

- **One block per method.** Every `pub trait` in `poulpy-hal/src/api` has contract blocks naming only its methods (a `Type::method(..)` path counting by its last segment), each method in exactly one block, shared only by word-for-word identical contracts (` / ` or `*`).
- **Block syntax.** A block is ```` ```text ````, an `op ` line, one aligned `key value` line per key (space-indented continuations) and ```` ``` ````, directly above `pub trait` (only doc lines, attributes and blank lines between) or in a grouped trait's method doc; api and delegate docs are plain ASCII.
- **Keys and values.** Keys are `op`, `class`, `mutation`, `definition`, `domain`, `requires`, `ensures`, `embed`, `fallback`, `override` and `test`, in that order, each at most once and non-empty, `op`, `class`, `mutation`, `domain` (`domain     -` for a support op without one), `ensures` and `test` required:
  - `class` is `basis`, `variant`, `derived` or `support`; `mutation` is `out-of-place`, `in-place`, `accumulate`, or `none` exactly for `support`;
  - every non-`support` block has one `definition`, a `support` block none;
  - `fallback` and `override` appear exactly on `derived` blocks and `variant` blocks whose `requires` names a `_tmp_bytes` (kept required: `fallback   none; required`, `override   required`), plus a defaulted `support` hook (`synchronize`).
- **Op line spells the signature.** An `op` line lists the declared parameter names in order without `self`, except in wildcard blocks, and a parameter change updates it and every `definition`, `domain` and `ensures` mention.
- **Test line names suite tests.** The `test` line lists, separated by `, `, the `pub fn test_*` suite functions exercising the op (a `_tmp_bytes` its op's, a new computing op its own, `test none` only for an untested `support` block), following every rename or removal.
- **Mutation follows the form.** `_assign` forms are `in-place` (`vec_znx_add_scalar_assign`, adding into one limb: `accumulate`), forms adding or subtracting their transformed or multiplied operand into the destination (`vec_znx_lsh_add`) are `accumulate`, other computing ops `out-of-place`, the raw complex transform `in-place`.
- **Grammar changes move together.** A grammar change (key, class, mutation value, `op` matching) updates `poulpy-hal/tests/contracts.rs`, its unit tests, `# Contract blocks` of `poulpy-hal/src/api/mod.rs` and every affected block in one PR, never relaxing a check for one block.

### 3.2. Content

- **Complete definitions.** A `basis` definition is a closed formula fixing every visible output; a `variant` or `derived` one may compose HAL ops with every argument (columns, `tmp, 0`, scratch), reading each destination as its value just before that call; each is written in full, only an identical `domain` or `embed` line reading `as for <sibling op>`.
- **What definitions leave unchanged.** Definitions end with `other columns of res are unchanged` when column-selected, state preserved limbs or coefficients on the definition line when in place or accumulating, and quantify every column when whole-object; input limbs past `a.size()` read as zero, an out-of-range input column only where stated, and every index but the destination limb `j` is bound on its line (`ell` when a parameter is named `j`).
- **Notation only.** Definitions and `domain`, `requires`, `ensures` and `embed` lines use only symbols of `# Value model`, `# Notation` and `# Canonical form` in `poulpy-hal/src/api/mod.rs`, a new symbol entering `# Notation` in the same diff with its arguments' meaning.
- **Domain lists every precondition.** `domain` or `requires` states every precondition a kernel asserts (ranges, degree relations, `res_k <= res.size() * res_base2k`, `step >= 1`, odd exponents and Galois elements, density) except column bounds and those the API module docs state once (the module serves the call degree, the scratch meets its query), and numeric bounds as unchecked caller obligations.
- **Density and degree phrases.** Where a kernel requires it, `domain` says per operand `a VecZnx or a window of one` or `a dense VecZnx` and its degree (`of degree N`, `of the same degree`, or `of any degree, the module's does not enter` for coefficient-wise reductions and products), `N` being the call degree read from `res`, the module degree spelled out (`MIN_DEGREE <= n <= the module's degree`) outside module support ops.
- **Ensures states the tail.** `ensures` states what destination limbs past the inputs' hold, never weakening or contradicting the definition, and `the digits are not renormalized` wherever digits can leave the canonical range (sums, differences, accumulating shifts, `X^p - 1` products, CI maps, entrywise matrix sums).
- **Rounding through rnd and canon.** A normalizing, rounding or decomposing op takes explicit `res_k` or `k`, is defined through `rnd(x, k)` (`canon(v, b, k, L)` for a canonical column), states digit ranges and congruence modulo 1 to `rnd(..)` in `ensures`, never an equality or a value in `[-1/2, 1/2)`, and the radix range and input bound (`[-2^62, 2^62]`, big coefficients `abs <= 2^126`) in `domain`; no new rounding mode is added.
- **Exact integer results.** An integer op never says "approximately", and a formula whose intermediates may leave the coefficient type writes `wrap(..)` or bounds them in `domain` (`docs/review/workspace.md` section 2).
- **DFT results through idft.** Contracts state DFT results through `idft(..)` and prepared operands through the polynomial they read as, never a layout, slot order, word type, byte representation or cross-backend byte equality (the raw complex transform alone fixes `rev_m`, `omega(m,r)`); slot-order helpers live in backend crates, poulpy-hal keeping only `check_galois` and `check_degree`.
- **Degree embedding.** Only slots an `embed` line names take a dense degree-`n` operand (`n` a power-of-two divisor of `N`), matching its `switch_ring_{n->N}` bit for bit, other operands at degree `N` and windows there as wide as `res`:
  - a derived op declares a slot only if every op its fallback feeds accepts it;
  - in the convolution only the prepared right operand embeds, prepares are not embedding-aware (a degree-`n` operand is prepared at `n`), and a backend may reject an embedded degree below its transform block width;
  - `embed` ops name their family's embedding test, and a new or extended slot updates `# Degree embedding` in `poulpy-hal/src/api/mod.rs`;
  - contracts, docs, test and kernel names say "embedding", never "sparse" or "compact".
- **Support blocks.** A new allocation, sizing, carving, plan or module trait's `support` block bounds dimensions and degree in `domain` (`n: a power of two, MIN_DEGREE <= n <= the module's degree` for allocations and sizes, at most the module's degree for carves, a take fed to a kernel obeying that kernel's floor) and leaves contents unspecified in `ensures`.
- **Scratch lines.** A scratch-taking op `requires` `scratch >= <query>(<arguments>)` with its own query (`vec_znx_lsh_tmp_bytes(res.size())`) and a scratch-free op has neither, a query's `ensures` names the ops and sizes it serves, never a byte formula or the fallback's carve, and a family query lists, and is named by, every op it sizes, a new op extending that list and the default's bound.
- **Fallback and override lines.** A derived op's `fallback` describes its body exactly, step by step (temporaries' limbs, columns and degree, nested calls in order, checks), updated with every body change, and its `override` reads `allowed, with <its query>`, `allowed, scratch-free` or, for a sampler, `allowed, drawing the same values`.
- **Notation changes are behaviour changes.** Changing the meaning of a Notation symbol or the canonical form (the `rnd` tie rule) updates `poulpy-hal/src/api/mod.rs`, the oracle and every backend kernel in one PR with a `**Breaking, behaviour:**` entry, never by regenerating fixtures alone.

## 4. Delegates

Generic rule: `docs/review/workspace.md` section 3 ("Delegates are a plain dispatch").

- **Delegates use the family macro.** Ring-arithmetic and query delegates are one `impl_<family>_delegate!` invocation per trait, fenced `Backend<ZnxWord = i64> + Hal<Family>Impl` (standard-only ops via the `monomial` and `ci` arms of `impl_vec_znx_delegate!`), and a new family macro keeps the fence and updates the macro count in the fence comment of `poulpy-hal/src/delegates/vec_znx.rs`.
- **Support delegates are plain.** Only allocation, `bytes_of_*`, plan-constructor, module and scratch delegates are plain `impl` blocks, bounded only by `B: Backend` (plus `HalModuleImpl` for module hooks, the OEP family for a plan constructor), forwarding to the owned `alloc` or inherent `Module` allocator and to `Backend::bytes_of_<layout>`.

## 5. OEP families and derived defaults

- **Family trait shape.** A family is a `pub unsafe trait Hal<Family>Impl` in `poulpy-hal/src/oep/hal_impl.rs`, re-exported by `oep`, whose `# Safety` cites the backend safety contract and the aspects it touches, or reads "Same contract as [`HalVecZnxImpl`]", never restating contract text (`docs/review/workspace.md` section 3).
- **Supertraits are the composition graph.** A family's acyclic supertraits include every family its default bodies dispatch into; a new family or edge updates the graph and topological order of the `poulpy-hal/src/oep/mod.rs` docs, and a new family-wide `_tmp_bytes` joins their exception paragraph.
- **OEP method shape.** Only `HalModuleImpl::new(n)` takes no module, and a method's `usize` `_tmp_bytes` is declared right before it, a family-wide one before the first body it sizes (`docs/review/workspace.md` section 3).
- **File layout per family.** `api/<family>.rs` imports only `layouts` and `source`, and a new family adds `mod <family>;` plus `pub use <family>::*;` to `api/mod.rs`, `mod <family>;` to `delegates/mod.rs` and `pub mod <family>;` to `test_suite/mod.rs` (`docs/review/workspace.md` section 3).
- **Default bodies are one call.** A default body is exactly `crate::oep::<op>_derived::<Self>(module, <its arguments in order>)` (`::<Self, R>` with a layout generic), a `_tmp_bytes` default `crate::oep::<op>_tmp_bytes_derived::<Self>(module, ..)`.
- **Derived functions.** A derived op is `#[doc(hidden)] pub fn <op>_derived<BE>(module: &Module<BE>, <the OEP method's arguments>) where BE: <its OEP family>` (plus its layout generic `R`) in `poulpy-hal/src/oep/derived.rs`, with a `<op>_tmp_bytes_derived` twin when it takes scratch (one per family-wide query), private shared helpers, and no caller above poulpy-hal but a gated override's fallback (`docs/review/workspace.md` section 14).
- **What a derived body uses.** A derived body uses only `BE::<oep method>` calls (never a sibling `<op>_derived`), backend views with `to_backend_ref`/`to_backend_mut`, the hal view helpers (`*_backend_ref_from_mut`, `vec_znx_reborrow_backend_mut`, `mat_znx_at_backend_*`, `scalar_znx_as_vec_znx_backend_ref_from_ref`, `window_limbs`), shared checkers (`check_galois`), `take_*_scratch`, `Backend::bytes_of_*`, `Backend::scratch_aligned` and a sampler's `source.new_seed()`, and never narrows a DFT or prepared view.
- **Derived body defines the op.** A derived body's doc states its composition and every contract it fixes (limb selection, offsets, zeroed or untouched limbs, empty inputs, failures, column alignment, caller preconditions), which overrides reproduce bit for bit, through `idft` and normalization for DFT results and as the same canonical value for non-canonical digits (`docs/review/workspace.md` section 2).
- **In-place forms use a temporary.** An `_assign` derived body calls the in-place OEP form or computes from `vec_znx_backend_ref_from_mut` into a scratch temporary copied back by `vec_znx_copy`, never one buffer as source and destination, and a body writing `res` before reading states "`res` must not alias `a` or `b`" in its doc.
- **Composites validate up front.** A looping derived body asserts, before dispatching, every dimension the loop relies on in one tuple comparison with a static message (`"<op>: res and a differ in <what>"`) and every term's validity (`check_galois` on each), leaving per-operand checks to the kernels (`docs/review/workspace.md` section 4).

## 6. Backend, Module and degree

- **Module constructors enforce the cap.** `HalModuleImpl::new` returns its module through `Module::from_nonnull` or `Module::from_raw_parts`, which assert `n` a power of two at most `MAX_RING_DEGREE` (`docs/review/workspace.md` section 6).
- **The degree floor.** `Backend::MIN_DEGREE` defaults to 8, a backend with fixed-step kernels raises it to the smallest degree they handle, and an `impl_backend_from!` backend inherits its source's (`docs/review/workspace.md` section 6).
- **Standard-only families.** A standard-ring op starts its `domain` with `standard ring` (CI maps: `standard module of degree at least 2N`) and lives in `HalVecZnxCIImpl` (`Backend<Ring = Standard>`) or the unbounded `HalVecZnxMonomialImpl`, implemented on standard instantiations only (`docs/review/workspace.md` section 6).
- **Forward every Backend override.** `impl_backend_from!` forwards every defaulted `Backend` constant (`MIN_DEGREE`, `DFT_LIMBS_CONTIGUOUS`, `SCRATCH_ALIGN`) and overridden sizing method, new ones in the same diff, and every layout marker both ways, other traits (`MaxBase2k`, `ScratchWorkers`, `HalModuleImpl`, OEP families) implemented beside it.
- **Host module stays minimal.** `HostBytesBackend<R>` implements only `Backend` and `HalModuleImpl`, with no OEP compute family, `MaxBase2k` or table state.
- **Radix queries need a model.** `MaxBase2k::max_base2k(n, products, failure_bits, squaring)` and `Module::<BE>::max_base2k` return a `usize` (0 if none fits, at most the word width minus 2), and only a backend with a failure model implements it, once, as `impl<R: Ring> MaxBase2k for X<R>` over `max_base2k_ntt` or `max_base2k_fft64`, or by forwarding to its source.
- **Module handles are immutable.** `Module<B>` stays `Send + Sync`, a backend handle changing after `HalModuleImpl::new` only through internally synchronized state; scheme plans live in its `ModulePlanCache` (`ModulePlanCacheProvider`), one zero-sized key type per plan family covering every degree, built in `with_or_create` by an initializer never requesting its own key, never in a global cache.
- **Deferred execution.** Every backend call is logically synchronous: a backend defers execution only under the synchronization contract of `poulpy-hal/docs/backend_safety_contract.md` (submission order, transfer waits, borrowed host memory, storage release), overriding `HalModuleImpl::synchronize`, detecting the conditions it reports on the host before returning, from layout metadata only, and panicking on a later device failure by the next transfer or `synchronize`; library code never relies on `synchronize`.

## 7. Layouts, views and memory

- **Aligned storage.** Host-owned `AlignedVec<T>` (`AlignedBuf` for bytes) comes from `alloc_aligned`, `alloc_aligned_custom` or `AlignedVec::zeroed`, keeps its `T: Copy + bytemuck::Zeroable` bound, frees with its own `Layout` and gives an empty buffer an aligned dangling address, not `NonNull::dangling` (`docs/review/workspace.md` section 7).
- **Owned buffers may be padded.** Owned buffer lengths are checked against `padded_bytes(bytes_of_*)` or as at least the logical length, never for equality with `bytes_of_*`; host-to-backend copies use the length-tolerant transfer hooks, and `transfer_buf_into` gets both buffers from one allocation path.
- **Byte constructors check lengths.** A constructor taking ownership of caller bytes (`from_bytes`) asserts a length of `padded_bytes(<bytes_of>(..))`, callers of the unchecked `from_data` and `from_shape` validate, and `raw`/`raw_mut` assert once per call that the element view fits.
- **Checked size arithmetic.** Layout byte sizes, element counts and window shapes, `Backend::bytes_of_*`, allocation and carving use `checked_product(&[..], "<what>")` in poulpy-hal and `checked_mul`/`checked_add` with a static `expect` in backend overrides (`docs/review/workspace.md` section 4).
- **Zeros come from zeroing paths.** Zeros come from `Backend::alloc_zeroed_bytes`, `vec_znx_alloc_zeroed::<BE>`, inherent `Module` allocators, documented zero-initialized constructors or explicit zeroing, never from `*Alloc`, `Backend::alloc_bytes` or `ScratchOwned::alloc` (`docs/review/workspace.md` section 5).
- **No mutating resize.** A HAL layout's `size` never changes after construction (no `set_size`, layout `with_size` or capacity), fewer limbs going through borrowed views (`vec_znx_backend_mut_with_size`, `with_size_mut`, `with_limb_range_mut`, `window_limbs`).
- **Where windows are accepted.** Windows exist only on `VecZnx` and `VecZnxBig` (`VecZnxDft::from_shape` and `with_shape` reject one); coefficient-wise ops (normalize, shifts) accept them, and ring ops (rotate, automorphism, `mul_xp_minus_one`, CI maps), DFT-domain ops and prepares reject them at kernel entry with `assert_dense`, their `domain` saying so.
- **Whole-buffer helpers assert density.** Every whole-buffer helper of a window-capable layout (`raw`, `raw_mut`, `as_ptr`, `as_mut_ptr`, `digest_u64`, `to_owned_deep`, `to_host_owned`, `into_data`, `read_from`/`write_to`, `into_backend`, `into_big`, equality, hashing) asserts density.
- **Narrowed DFT views need capability.** Every strict `VecZnxDft` narrowing (`with_size_mut`, `with_limb_range_mut`) or indexed access (`zero_at`) panics unless `Backend::DFT_LIMBS_CONTIGUOUS`, the full range working on every layout; generic narrowing code states `const { assert!(BE::DFT_LIMBS_CONTIGUOUS, ..) }`, and a backend with another DFT layout overrides the dependent OEP methods with their queries.
- **Element views of backend-sized storage.** DFT, big and prepared buffer lengths come from `Backend::bytes_of_*`, never the word size; host element access (`raw`, `at`, `zero`, `Display`) on them needs byte size equal to element span, which a new `ZnxView` over such storage asserts in `validate_element_view`, a helper also serving packed buffers branches on the element span, and a container without flat (col, limb) indexing exposes only `raw`.
- **Hints select representations only.** A prepared layout's `PrepareHint` lives in its shape and every sizing, allocation, carve and wrap call, and no definition depends on it: `prepare` writes the destination hint's representation, applies accept every hint, copies and row extractions state and assert equal hints, and single-representation backends size hints equally (`test_word_compat_prepare_hint_sizes`).
- **The byte-level exception.** Only the word-compat suite compares `VecZnxDft`, `SvpPPol` and `VmpPMat` bytes, between backends declaring the layout marker over an exact word, and opaque `from_bytes` carries only value-agnostic operands (`docs/review/workspace.md` section 6).
- **Layout-compatibility markers.** `into_backend::<B2>()`, bounded on `*LayoutCompatible<B2>`, is the only zero-copy move, asserting equal `bytes_of_*` (and density on `VecZnxDft` and `VecZnxBig`) first and keeping the storage type; a marker, an `unsafe` claim of byte-identical buffers for every shape, is declared per family, never from a shared `DftWord`, with word-compat tests, a new opaque family adding the reflexive blanket impl, `into_backend` and two `impl_backend_from!` lines.
- **Byte moves through buffer traits.** Raw bytes move by `transfer_buf_into(src, dst)` into a caller-allocated buffer, new buffer types implement `CopyToHost`/`CopyFromHost` (`as_host_bytes*` `Some` only for host memory) and never name a backend pair, typed layouts move with core `TransferInto` (`docs/review/core.md` section 12), and only coefficient-domain layouts move by bytes, host-staged ones bounding `HostStaged` with `ZnxWord = i64` (`docs/review/workspace.md` section 7).
- **Equality and Debug.** Opaque layouts (`VecZnxDft`, `VecZnxBig`, `SvpPPol`, `VmpPMat`, `CnvPVecL`, `CnvPVecR`, new ones) compare, and hash where provided, as same shape and bytes, with no bound on the word (`docs/review/workspace.md` section 7).
- **A new layout's pieces.** A new HAL layout lands with:
  - a `#[repr(C)]` `*Shape` with `const` accessors, `ZnxInfos` (explicit `poly_count`) and `VecZnxInfos` (one flat `cols`) or `MatZnxInfos` (`rows`, `cols_in`, `cols_out`);
  - `DataView`/`DataViewMut`, the `*Owned`, `*BackendRef` and `*BackendMut` aliases, `*ToBackendRef`/`*ToBackendMut` on owned and borrowed forms, and the `*Reborrow*` traits;
  - `<Layout>Alloc`, `<Layout>BytesOf` (if opaque) and a `take_<layout>_scratch` wrapping `take_region` with `from_data` into a `*ViewMut` of `poulpy-hal/src/layouts/scratch_views.rs`, all sized by one `Backend::bytes_of_<layout>` (when backends may size it, forwarded in `impl_backend_from!`).
- **Serialized layouts.** Only `ScalarZnx`, `VecZnx` and `MatZnx` implement `WriterTo`/`ReaderFrom`, as little-endian `u64` shape fields, a `u64` byte length and exactly the logical bytes, never padding; readers check shape product times word size against the length and the receiver's capacity (`InvalidData` before reading) and commit the shape after `read_exact` (`docs/review/workspace.md` section 11).

## 8. Scratch

Generic rules: `docs/review/workspace.md` section 5.

- **Arena mechanics.** Chunk lengths passed to `split` are rounded with `worker_scratch_bytes::<BE>`, and `wipe` gets the op's own `_tmp_bytes` on the arena it received, after its carves are dead.
- **Derived queries mirror their bodies.** `<op>_tmp_bytes_derived` reports exactly what `<op>_derived` carves at the module degree, a temporary alive across a nested call as `BE::scratch_aligned(BE::bytes_of_<layout>(module.n(), cols, size))` plus that call's query at the sizes passed (`min(a_size, b_rows)` in `vmp_apply_dft`), a lone temporary unrounded.
- **Derived carves and zeroing.** A derived body carves each temporary at `ZnxInfos::n` of the operand the nested op reads and zeroes every temporary column it reads or accumulates into unless fully written first, even where the next kernel zeroes the tail.
- **Family-wide shift queries.** `vec_znx_lsh_tmp_bytes` and `vec_znx_rsh_tmp_bytes` cover their whole family (out of place, `_add`, `_sub`, `_assign`, new ops included); an override of one body may leave the family query on its default, an override of the query still covers the bodies left on default, and a new family-wide query states this on its trait and in `poulpy-hal/src/oep/mod.rs`.

## 9. What every backend kernel must guarantee

Every kernel of a HAL family `unsafe impl` guarantees these, beyond `poulpy-hal/docs/backend_safety_contract.md` and `docs/review/workspace.md` section 4.

- **Degree check first.** Every kernel whose `domain` involves the module degree calls `check_degree::<BE>(module.n(), n)` once at entry, `n` from `res` (or the operand setting the call degree), before any plan or table fetch, then checks other operands against `n` ("operand degree differs from the result degree"), or an `embed` slot as a power of two dividing `n` at or above the floor; a kernel whose `domain` says the module's degree does not enter checks only the degree relations it states.
- **Reject exactly the domain.** A kernel rejects before any write exactly what its `domain`, `requires` and the API module docs exclude, plus out-of-range columns and only limits its contract names (an embedded right convolution operand below the block width), so every kernel assert has contract text and every `domain` restriction a check.
- **Window refusals.** A window-rejecting kernel calls `poulpy_hal::layouts::assert_dense(v, "<name>")` at entry, `<name>` being the HAL op name (`vec_znx_rotate`, preferred) or the kernel function's name, and `"<Type>::<method>"` in a layout method, never a generic word; coefficient-wise kernels honour window offsets and strides.
- **Galois elements are checked.** Every kernel or derived body applying a `b_galois` term calls `poulpy_hal::layouts::check_galois` on it at entry ("convolution: b_galois must be odd"), on every term of a sum before the first write.
- **Embedded operands cost no more.** A kernel reads an embedded operand through the backend's slot correspondence (no staging gather), bit for bit the dense result, at no more cost than the dense apply.
- **Static messages on secret paths.** In poulpy-hal and its kernels the paths a secret or plaintext reaches include the `encode_*`/`decode_*` codecs, `svp_prepare`, the DFT of a secret and the `AlignedVec` sizing reached from secret-key size helpers, whose messages format nothing from that operand, length and shape included, `check_degree`'s degree aside (`docs/review/workspace.md` section 4).

## 10. Documentation and CHANGELOG

- **API prose is one sentence.** In `poulpy-hal/src/api` a trait doc is one sentence, an empty `///` line and its block (the sentence alone when its blocks sit on its methods), and a method doc one sentence on what the destination receives or the method returns (then an empty line and its block in a grouped trait), without `# Arguments`, `# Panics` or `# Examples`, diagrams, restated `domain` or `ensures`, rationale or cost claims.
- **OEP method docs.** A defaulted HAL OEP method documents what it computes and "Default body: `<op>_derived`, <the composition in words>" (a query: what its default sizes), a variant kept required begins "Required, not derived: <the temporary its signature cannot supply and why>", a family-wide query names the bodies it covers and says a partial override leaves it on the default or returns enough, and a basis method has no doc.
- **Docs name roles, not backends.** Hal rustdoc, contract blocks, suite docs and `poulpy-hal/docs/backend_safety_contract.md` name roles ("a comparison backend"), never a device API, a backend-internal representation or a backend as the suites' comparison or default (`docs/review/workspace.md` sections 1 and 13).
- **Safety contract holds obligations.** A new backend capability or obligation (`DFT_LIMBS_CONTIGUOUS`, deferred execution, a transfer or aliasing rule) enters `poulpy-hal/docs/backend_safety_contract.md` with its hook (`docs/review/workspace.md` section 13).
- **Review is the only check.** Every new private or `pub(crate)` hal item has a caller, every new intra-doc link resolves (methods as ``[`name`](Trait::method)``), and nothing becomes `pub` to silence an unused warning (`docs/review/workspace.md` section 13).
- **CHANGELOG classification.** Under ``### `poulpy-hal` `` (`docs/review/workspace.md` section 17):
  - a new required OEP method or family, or a new argument or field an overridable method reads (`CnvDftAccTerm`), is `**Breaking:**` and says what out-of-tree backends must add, explicitly when an override ignoring it still compiles and computes wrong results;
  - a new derived op in an existing family is a plain entry;
  - a renamed, removed or re-signed `poulpy_hal::test_suite` function, helper or module is `**Breaking:**` with old and new paths, every in-tree registration moving in the same PR;
  - a Notation meaning change is `**Breaking, behaviour:**` (section 3.2).

## 11. Tests and registration

Generic rules: `docs/review/workspace.md` sections 15 and 16.

- **Where HAL tests live.** HAL tests are `pub fn test_<op>[_<aspect>]`, declared on a line starting `pub fn ` (not macro-generated), in `poulpy-hal/src/test_suite/<family>.rs` (`svp.rs` and `vmp.rs` for `svp_ppol` and `vmp_pmat`), default-body pins in `derived.rs` unless the op's cross-backend test runs the derived function, and cross-cutting checks in `window.rs`, `embed.rs`, `word_compat.rs`, `transfer.rs` and `serialization.rs`, a new file declared `pub mod` in `test_suite/mod.rs`.
- **Test names.** HAL tests are `test_<op>`, or `test_<family>_<case>` for a family-wide check, embedding checks `test_<family>_embed[_<ops>]` and rejections `..._rejected` or `..._rejects_<what>`, registered under the same name (`test_x => poulpy_hal::test_suite::<module>::test_x`).
- **Signatures follow the macros.** A HAL test takes `(params: &TestParams, module: &Module<BE>)` for `backend_test_suite!` or `(params: &TestParams, module_ref: &Module<BR>, module_test: &Module<BT>)` for `cross_backend_test_suite!`, another signature only for an object the macros cannot build, called from a backend `#[test]`; its bounds are `TestBackend`, its API traits and, for an `oep::*_derived` call outside `HalVecZnxImpl`, that family.
- **Suites use the given modules.** A suite function builds no `Module`, runs ops as `module.<op>(..)`, and below the API calls only the pinning tests' `oep::<op>_derived` and module-free `Backend` items (transfer hooks, `bytes_of_*`, `MIN_DEGREE`, capability flags).
- **Degree sweep.** Suite tests compute at `params.n` (`params.size` is the module degree, not a limb count), adding a `module.n()` leg when needed and filtering lower degrees by `BE::MIN_DEGREE` (a module-independent op: every degree its `domain` admits), and HAL registrations set `n` to `MIN_DEGREE` below `size`, except statistical sampling, named large-ring and core noise suites.
- **Register on every backend.** A new HAL test joins, in the same PR, the `backend_test_suite!` or `cross_backend_test_suite!` lists of every implementing backend type in every crate (the oracle's conjugate-invariant tables and the FFT64 and NTT families included, where they exist), a default-body pin joining each `derived` suite, and Rayon twins register their overridden ops at sizes past their parallel-work floors.
- **CI filter tokens.** A HAL test name, or a backend `#[test]` calling a module-free suite function (`raw_transform_matches_contract`), carries a base filter token of `.github/scripts/test-backend.sh` (`test_vec_znx`), a new prefix extending the list.
- **Arenas are exact.** A HAL arena is a plain, unpoisoned `ScratchOwned::alloc` of each side's own queries (`module_ref.<op>_tmp_bytes`, `module_test.<op>_tmp_bytes`), the tested op alone on its arena, and a direct derived call on `<op>_tmp_bytes_derived`.
- **Cross-backend protocol.** Inputs are drawn once on `module_ref` and uploaded, coefficient results compared bit for bit, `VecZnxBig` results after `vec_znx_big_normalize`, and `VecZnxDft` and prepared results only through `vec_znx_idft_apply` and `vec_znx_big_normalize` (or a product through them).
- **Check the contract independently.** A new op's test also checks a backend-independent expectation (host computation or API recomposition) on the edge inputs its domain admits: rounding ties, extreme and non-canonical digits, empty and mismatched sizes.
- **Sweep sizes, columns and windows.** A new op's test sweeps destination sizes below, at and above the inputs, every column and parameter edge (offsets, steps, `cnv_offset` past the product), accepted windows in `poulpy_hal::test_suite::window` (a coefficient and a strided limb window, matching the op on the materialized window, the outside untouched), and `embed` slots against the dense `switch_ring` embedding in `test_suite/embed.rs` or the convolution embedding test.
- **Window rejections are tested.** A new window-rejecting op gets a panic leg in `test_vec_znx_window_rejected_by_ring_ops` beside the accepting coefficient-wise control leg.
- **Dirty destinations.** Destinations start from random digits (differing per side out of place), a sentinel or a poisoned template, multi-column ones written at a non-zero column, tails and unselected columns compared after the call.
- **Input preservation on the backend.** An input-unchanged check compares the backend operand downloaded after the call (or its `digest_u64`) with a pre-call copy, or repeats the call, never a pre-upload host digest.
- **Rejection tests.** HAL rejection tests use `std::panic::catch_unwind(AssertUnwindSafe(..))` ("<op> accepted <condition> instead of panicking"), pin only shared-helper messages (`check_galois`), check the destination unchanged on the same backend (bytes, or `idft` and normalization) and cover every kernel check (a column equal to `cols`, a degree mismatch, empty operands, and for a composite an operand mismatch and an invalid term past a fused group).
- **Testing a derived op.** A derived op's test checks `<op>_derived::<BE>` and `module.<op>` bit for bit against an oracle of other API calls (never the op under test) or host computation, DFT and big results after normalization, canonical forms where decompositions differ.
- **Sampler tests.** A sampler test pins the stream against a backend-independent expectation from the seed (radix endpoints, a partial last limb, poisoned tails, unselected columns), checks that a call consumes exactly one 32-byte seed, and the multi-column form against per-column calls.
- **Capability legs are gated.** A leg needing an optional capability runs only when every backend involved declares it (`if BR::DFT_LIMBS_CONTIGUOUS && BT::DFT_LIMBS_CONTIGUOUS`), the op staying tested everywhere.
- **Shared suite helpers.** A helper shared by suite files lives once, `pub(crate)` in its concept's file (`assert_canonical` in `vec_znx.rs`; `idft_into_alloc`, `dft_of_uploaded_vec_znx`, `idft_apply_to_host` in `vec_znx_dft.rs`), imported, never redefined.
- **Unsafe code gets Miri tests.** New or changed `unsafe` code in poulpy-hal gets a Miri-sized `#[cfg(test)]` unit test inside `poulpy-hal/src` that reaches it, foreign calls compiling out under `cfg(miri)` (`advise_hugepage`).

## 12. Do not report

Never report or request these, in addition to `docs/review/workspace.md` section 18:

- A missing `MaxBase2k` impl without a failure model or on `HostBytesBackend`, or a request for a placeholder radix or an `Option` return.
- The empty `unsafe impl` every backend needs for an op's own layout family.
- HAL `_tmp_bytes` over-reservation below the module degree, or a request for a degree argument on a HAL query.
- A proposal to store a radix, precision or canonical flag on a HAL layout.
- The floating-point error of `NegacyclicFFT`.
